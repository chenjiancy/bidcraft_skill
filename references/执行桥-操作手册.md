# 执行桥操作手册（bidcraft-server v3.0 · POST /api/exec）

> 位置：`references/执行桥-操作手册.md` ｜ 版本：3.0 ｜ 配套：`scripts/bidcraft_server.py`
> 一句话：把「只读 HTTP 桥」升级为「执行桥」——UI 点按钮真跑 CLI、真出产物，不再是演示原型；
> 同时守住三条安全底线：**白名单唯一入口 / 写操作必须 confirm / 高风险命令永不暴露**。

## 1. 它解决什么问题

| 阶段 | 桥的能力 | UI 表现 |
| --- | --- | --- |
| v1/v2（只读桥） | 只能 GET 取数 | UI 能看清单/预设/校验，但按钮点了不出真产物 → 演示原型 |
| v3（执行桥） | GET 只读 + POST `/api/exec` 白名单执行 | UI 点「出样张/体检/留痕/报告」→ 真跑 CLI → 真落盘 docx/html/json |

核心不变：**CLI 仍是唯一事实源**。桥不持有业务逻辑，只是把 HTTP 请求翻译成白名单内的 CLI 命令。

## 2. 启动与基本用法

```powershell
python scripts/bidcraft_server.py --host 127.0.0.1 --port 8765 --root <软件根> --enterprise <企业>
```

- 默认只绑 127.0.0.1（仅本机可访问）；内网访问需显式 `--host 0.0.0.0` 并自行加鉴权。
- 不传 `--root` 时用 `BIDCRAFT_LIB_ROOT` 或 `./素材库`。
- `--enterprise` 可省（单企业自动解析；多企业时必须指定，与 CLI 规则一致）。

## 3. 执行桥请求格式

```
POST /api/exec
Content-Type: application/json

{
  "command": "tpl-design--specimen",   // 白名单 key（见 §4 或 /api/capabilities）
  "args": {"name": "示例-标准技术标.json", "fill": "enterprise_name=甲公司;project_name=智慧园区"},
  "confirm": true                       // write 命令必须为 true；read 命令可 false
}
```

响应：

```json
{
  "ok": true, "command": "tpl-design--specimen", "mode": "write", "exit": 0,
  "payload": { ... },                    // json 命令（CLI --json 原样）
  "output": {"stdout": "...", "stderr": "..."}   // 文本命令；截断 20000 字符
}
```

错误情形（HTTP 均 200，看 `ok`/`error`）：
- `ok:false, error:"…不在执行桥白名单…"` → 命令不在白名单；
- `ok:false, error:"…高风险操作…"` → 命令被 deny（见 §5）；
- `ok:false, error:"…必须显式确认：confirm:true…"` → write 命令没带 confirm；
- `ok:false, error:"参数校验失败…"` → 参数非法（注入/路径逃逸/项目不存在）；
- `ok:false, error:"CLI 超时…"` / `"CLI 失败…"` → CLI 侧问题，看 output。

## 4. 白名单（唯一入口）

| key | 模式 | 参数 | 说明 |
| --- | --- | --- | --- |
| `tpl-design--list` | read | — | 模板清单（CLI `--json` 原样） |
| `tpl-design--show` | read | `name` | 模板详情（含暗标派生 15 组） |
| `tpl-design--validate` | read | `name` | 模板校验问题清单 |
| `tpl-part--list` | read | — | 部件库清单 |
| `tpl-part--show` | read | `name` | 部件内容 |
| `tech-layout--list` | read | — | 排版预设 + 版面范式（文本） |
| `tech-status` | read | `project` | 技术标写作状态表 |
| `tpl-design--specimen` | **write** | `name`、`fill`（可选） | 出模板样张 docx |
| `tech-layout--preview` | **write** | `project`（可选）、`enterprise`（可选） | 排版样张 docx 预览 |
| `m9-verify` | **write** | `project` | 项目自检体检（红绿灯） |
| `m9-evidence` | **write** | `project` | 投标留痕包 |
| `tender-report` | **write** | `project` | 投标要点 HTML 报告 |
| `tender-rule` | **write** | `project` | 通道A 文档解析（规则引擎落盘 文档解析_<项目>.json） |
| `tender-agent-parse` | **write** | `project` | 通道B 语义解析（agent 桥·CodeBuddy CLI，落盘 投标要点，耗时长 timeout 900） |

- **read**：查询/校验，无副作用，无需 confirm；
- **write**：会**落盘可逆产物**（样张/预览/体检/留痕/报告/通道A解析），必须 `confirm:true`。产物均可删除重建、不覆盖正式文件、不推进状态机，故允许经桥执行；真正的高风险写操作见 §5。
- **project 参数形态（v3.1 修正）**：`--project` 传**项目名**（CLI 契约），服务端用 `_project_dir` 校验目录真实存在于 `<企业根>/项目级/` 边界内——校验用解析、传参用名字。此前 v3.0 把绝对路径当项目名传入导致真实执行失败（tender-rule/m9-verify/tender-report 实测暴露，已修）。

## 5. 高风险命令（永不通过执行桥暴露）

应用类 / 覆盖类 / 删除类 / 状态推进类，一律 403，只走 CLI + 人工确认闸门：

```text
tpl-design--apply    （模板落盘登记）
tpl-part--scan       （部件库拆解落盘）
tech-layout--apply   （专家包应用组合）
tech-export          （真实项目成稿导出）
tech-outline/report/parse/rewrite/ctx （章节树落盘 / 闸门②确认 / 状态推进）
tender-parse/diff/annex/gap/rule/extract/fmt/check/show（招标解析与派生）
fill-tpl             （商务标/成稿生成）
remedy-gen/done/archive（补救动作与归档）
assets-archive / asset-upload/propose/apply/trash/rm-project/cleanup-trash/reconcile（素材库写操作）
docx-read / docx-audit（文档读取审计）
```

完整集合见 `scripts/bidcraft_server.py` 的 `EXEC_DENY_COMMANDS`（capabilities 的 `denyCommands` 同步暴露给 UI 展示）。

## 6. 安全边界（为什么这样设计）

| 措施 | 实现 |
| --- | --- |
| 白名单唯一入口 | 非 `EXEC_COMMANDS` 的 command 一律拒绝 |
| 无 shell 拼接 | `subprocess.run([python, cli, --root, …, 参数列表])`，参数不进 shell |
| 参数防注入 | `_simple_value`：拒绝 `..`、盘符、绝对路径、控制字符、超长（200） |
| 项目目录边界 | `_project_dir`：`<企业根>/项目级/<项目>` resolve 后必须仍在企业根内且真实存在 |
| 写操作闸门 | write 命令缺 `confirm:true` → 拒绝（零执行） |
| 高风险永不暴露 | deny 集合显式列出，白名单之外即使未来加命令也先过此闸 |
| 超时与截断 | read 120s / write 300s；stdout/stderr 截断 20000 |
| 默认本机 | 绑定 127.0.0.1；`--host 0.0.0.0` 需自行鉴权 |

## 7. 示例（UI 接线后的效果）

- 只读查询：`{"command":"tpl-design--list","args":{}}` → 模板清单；
- 出样张（人工确认）：`{"command":"tpl-design--specimen","args":{"name":"示例-标准技术标.json","fill":"enterprise_name=甲公司"},"confirm":true}` → 真 docx 落盘，返回 `payload.file` 路径；
- 项目体检（人工确认）：`{"command":"m9-verify","args":{"project":"智慧园区"}}`（不带 confirm）→ 拒绝，提示先确认；带 confirm → 落盘 `自检/自检体检_智慧园区.json/.md/.html`；
- 恶意尝试：`{"command":"rm -rf /"}` → 白名单外拒绝；`{"command":"tech-status","args":{"project":"..\\..\\逃逸"}}` → 参数校验失败。

## 9. 已知边界（如实声明）

- **执行桥 ≠ 全功能 UI**：UI 变「真」的前提是按钮真调用 `/api/exec` 并展示结果——接线是 UI 侧工作（已交付：主工作台 execBridge 引擎 + 命令台 + 关键按钮接线，见 commit 53136d4）。
- **项目名参数形态（v3.1 修正）**：`--project` 传**项目名**，服务端 `_project_dir` 做目录存在与边界校验。v3.0 曾把绝对路径传入导致 tender-rule/m9-verify/tender-report 真实执行失败——integration 新增临时根真实执行用例后暴露并修复。
- **鉴权**：桥无鉴权，仅限本机；平台包装必须自加鉴权。

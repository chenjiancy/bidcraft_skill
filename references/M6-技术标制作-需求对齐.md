## 一、目标与形态

### 1.1 目标

在 M4 解析产物基础上生成**技术标（监理大纲/技术方案）**：按评分项组织章节、按招标格式要求控制篇幅、按素材清单注入事实、按选定写作风格与排版预设成文，产出可交付 docx，并输出可被 M7/M8 消费的结构化产物。

### 1.2 形态

| 维度 | 结论 |
|---|---|
| 正文形态 | **Markdown 分章**（`章节/ch-xx.md`），章标题由合并时统一添加 |
| 终稿形态 | **docx**（`产出/技术标_<项目>.docx`），套用排版预设 + TOC 域 + 页眉页脚 |
| 内容与版式 | **解耦**：正文 md 不含排版；版式由 `layout` 预设控制，改版式不动内容 |
| 生成主体 | **agent 写**（目录/正文/精修），**脚本查与存**（结构/覆盖/篇幅/敏感词/状态/导出） |
| 交付节奏 | 分章可审、可直改；批量写作受状态机与失败续写约束 |

### 1.3 与 M5 的边界（必须分清）

- **M5 商务标 = 确定性填充**：模板母版 + 素材清单，脚本执行，AI 不参与正文。
- **M6 技术标 = 语义生成**：正文必须 agent 创作，脚本不做语义判断。
- 因此 M6 采用 M4/M7 的**双通道范式**，不照搬 M5 的 `fill-tpl`。

### 1.4 用户职责

章节树确认（闸门①）、写作结果裁决（闸门②）、终稿确认（闸门③）、缺料与暗标口径决策、风格与排版预设选择。

## 二、产物定义

| # | 产物 | 内容 | 消费方 |
|---|---|---|---|
| A | `章节树.json` | dewey 编号章节 + `scoreRefs` 评分点映射 + `keyPoints` + `wordCnt` + `status` + `files` + `layout` | 本模块调度、M8 定位文本 |
| B | `章节/ch-*.md` | 分章正文（Markdown） | 人工审阅、合并导出、M8 主观分评审 |
| C | `章节/.meta/ch-*.json` | 上下文包快照（注入了哪些评分点/素材/术语），可审计 | 复盘、精修 |
| D | `检查/覆盖矩阵_<项目>.json/.md` | 通道A 六项检查结论（覆盖/编号/篇幅/暗标/一致性/残留） | 人工裁决、`tech-diff` |
| E | `检查/技术标检查报告_<项目>.html` | 单文件 HTML（KPI 速览 + 覆盖矩阵 + 硬问题 + 裁决区） | 闸门② |
| F | `产出/技术标_<项目>.docx` / `.md` | 合并终稿（docx 套预设 + TOC）+ 合并 md | 交付、M7 检查 |

**落位**：项目级 `<软件根>/<企业>/项目级/<项目名>/技术标/`（与 `招标解析/`、`商务标\`、`标书检查\`、`模拟评标\` 同级）。

## 三、流程与闸门

```
tech-init（建目录 + 校验 M4 就绪 + 抽取页数/格式约束）
   ↓
agent 编章节树 → tech-outline 结构校验
   ↓
【闸门① 章节树确认】← 未确认禁止 tech-ctx / tech-parse
   ↓
tech-ctx 逐章生成上下文包
   ↓
agent 逐章写作 → tech-parse 落盘（状态机 + 写后回读）
   ↓
tech-check 通道A 六项 → tech-report HTML
   ↓
【闸门② 写作结果裁决】← 有 error 级问题禁止 tech-export（除非 --force 并记录）
   ↓
tech-rewrite 精修（可选）+ tech-diff 双通道差异逐项裁决
   ↓
tech-export 合并 → docx（TOC + 页眉页脚 + 预设套用）→ 回读 + 页数回写
   ↓
【闸门③ 终稿确认】→ 交付；后续接 M7 / M8
```

**闸门纪律**：
1. 三个闸门均需用户明确确认，确认记入 `章节树.json.confirmLog`；
2. 闸门①未确认 → 程序化拒绝 `tech-ctx`/`tech-parse`；
3. `tech-diff` 差异必须逐项请求裁决，**不得静默判定"实质一致"后略过**（沿用 M4 v2.4）；
4. 一切产出真实执行，未跑脚本不得声称完成；回读失败必须报错暴露。

## 五、硬性约束（不可协商）

1. **不臆造**：材料没有的数据写 `{{待填:说明}}` 交人工；不得编造人名/业绩/金额/证书编号/规范条文号。
2. **素材未列不生成**：`dependsOnMaterials` 未声明的材料不注入、不展开。
3. **人员唯一来源 = M4 素材清单 `personnel`**：技术标不得自造人名，且须与商务标附表 7 一致。
4. **术语一致**：项目名/招标人/服务期统一取 `terminology`，各章称谓一致。
5. **暗标合规**：`bidMode=暗标` 时企业名/logo/联系人不得进正文；封面禁用 `image-underlay`；人员姓名按 D11 处理。
6. **单项目隔离**：所有输入输出路径必须在 `项目级/<本项目>/` 内，越界拒绝。
7. **闸门不静默**：三闸门均需明确确认并留痕；差异逐项裁决。
8. **可回滚**：重写正文前旧文件入 `.rewrite-trash/<时间戳>/`；导出覆盖前旧 docx 留 `.bak`。
9. **不读合同内容**：与 M4 一致，除用户明确要求外不引用合同条款。
10. **不做语义判断的脚本化**：脚本只做确定性检查，覆盖是否"真覆盖"由 agent/人工裁决。

## 六、排版预设需求（D8）

**落位**：共享级 `共享资源/技术标风格/layout-presets.json`，可增行表（增删不改代码）。

| 组 | 项数 | 内容 |
|---|---|---|
| 版面范式 | 7 | 单栏流式 / 表格化布局 / 双栏分栏 / 卡片式布局 / 左图右文 / 章节分隔页 / 数据行布局 |
| 配色方案 | 11 | 深靛蓝 / 暖棕金 / 松绿 / 砖红 / 钢青 / 炭灰极简 / 深海蓝金 / 墨绿暖橙 / 茄子紫银灰 / 黑白灰一点红 / 渐变蓝青 |
| 封面版式 | 4 | 满版色块 / 留白线条 / 图底压字 / 渐变 |
| 装饰强度 | 3 | 克制 / 标准 / 丰富 |
| 字体方案 | 5 | 政务公文风 / 工程务实风 / 现代商务风 / 典雅书卷风 / 暗标安全风（v0.6 新增） |
| 图文比例 | 4 | 无图 0:10（暗标推荐）/ 低图比 1:9 / 中图比 3:7（默认）/ 高图比 5:5（v0.7 新增） |
| 配图规则 | 5 | 上传优先 / 搜索补图 / AI 生图 / 混合策略（默认）/ 暗标安全（v0.7 新增，三来源：人工上传/联网搜索/AI 生成） |
| 配图排版 | 5 | 左右分栏（默认）/ 上下分栏 / 图文混排 / 图组并排 / 附图专页（v0.7 新增） |

**约束**：
1. 每套配色定义 5 组色值（`primary/accent/heading/tableFill/coverBg`）——已 T13 出色卡、用户确认后固化；
2. 字体默认 `gov-gongwen`（正文仿宋，沿用既有偏好），可在 `overrides` 覆盖具体字族；
3. 预设只影响 `tech-export`，不影响正文 md；
4. 暗标时强制 `cover != image-underlay`、`font == dark-safe`、**图片二选一**：`imageRatio=none`（零图）或 `dark-safe-img + appendix`；
5. 实现能力边界须披露：python-docx 不支持原生渐变/圆角，「渐变蓝青」「卡片式」以近似方式实现，不承诺像素级还原；图片渲染（灰度/打码/遮盖、图上标签、左右分栏）由 T10 tech-export 承载。

## 八、验收标准（逐条可验）

| # | 验收项 | 判定方法 |
|---|---|---|
| V1 | **评分点全覆盖** | 通道A 覆盖矩阵中 `kind=outline` 的每个评分项至少被一个章节 `scoreRefs` 引用，无遗漏 |
| V2 | **章节结构合法** | dewey 编号连续、父章存在、层级 ≤3、无重号 |
| V3 | **篇幅可控** | 估算页数 ≤ 招标 `pageConstraint.max`；不足 60% 报 warn |
| V4 | **正文可读且非空** | 每章落盘后回读：非空、字数 ≥ `wordCnt×0.7`、无未替换占位符 |
| V5 | **素材零编造** | 抽查人员姓名/业绩金额/证书编号全部可追溯至素材清单或标注 `{{待填}}` |
| V6 | **人员一致** | 技术标人员与素材清单 `personnel` 完全一致（姓名/岗位），无自造 |
| V7 | **暗标合规** | 暗标项目正文零企业名/logo/联系方式；封面非 `image-underlay` |
| V8 | **闸门生效** | 未确认章节树时 `tech-ctx`/`tech-parse` 返回失败；有 error 时 `tech-export` 拒绝（除非 `--force` 留痕） |
| V9 | **导出可用** | docx 可被 Word 打开、TOC 域存在且可刷新、页眉页脚正确、页数回写 |
| V10 | **版式生效** | 选定的版式/配色/封面/装饰/字体五组参数在 docx 中可见生效（v0.6 增字体维度） |
| V11 | **精修可回滚** | `tech-rewrite` 后 `.rewrite-trash` 可还原旧正文；差异逐项列出 |
| V12 | **双通道不静默** | `tech-diff` 差异条数与裁决记录条数一致，无未裁决项进入终稿 |
| V13 | **项目隔离** | 跨项目路径传入时抛 `LibraryError`，不读写他项目数据 |
| V14 | **状态机正确** | 各章状态迁移符合 `PENDING→CONTEXT_READY→WRITING→WRITTEN→CHECKED→CONFIRMED/FAILED` |

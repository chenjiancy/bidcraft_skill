## M1 素材库
- **目标**：企业投标素材（业绩库/资质/人员等）的采集、结构化归类、检索。**企业级**：落位于 `<软件根>/<企业>/企业级/`，按企业隔离。
- **输入**：用户提供的资质/业绩/人员/图片等文件（经收件箱进入 `<软件根>/<企业>/企业级/业绩库/收件箱`）。
- **输出**：结构化素材目录 + 素材台账（JSON/CSV，可按大类/子类/关键字/到期日/归属检索）+ 巡检问题清单。
- **依赖**：无（命名规范内置于 `scripts/_shared/naming.py`；M3 知识库落地后可回填分类标准）。
- **状态**：✅ 已交付（2026-10-01，v0.2；v0.6 起分包结构化 + 三层目录适配）
- **实现说明**：
  - `scripts/_shared/naming.py` —— 命名规范引擎（规则表 / 关键字清洗 / 日期归一 / 生成 / 校验 / 智能分类），纯逻辑无 I/O。
  - `scripts/_shared/core.py` —— 存储层（企业初始化三层结构、台账、收件箱批次、回收站、巡检、检索）。
  - `scripts/m1_assets/` —— M1 模块子包：全部 `cmd_*` 命令 + `register_parser(subparsers)`（CLI）。
  - `scripts/bidcraft.py` —— 统一入口薄壳：argparse 组装 + 调度（`init-enterprise` / `open-inbox` / `upload` / `sync-inbox` / `close-inbox` / `propose` / `apply` / `inspect` / `query` / `trash` / `cleanup-trash` / `rules` / `validate` / `classify` / `build-name` / `build-project-folder` / `ownership-check`）。
  - 需求依据：`references/M1-素材库-需求对齐.md`（v1.0 定稿，决策 Q1–Q16）。
  - 用法与字段：`references/M1-素材库-操作手册.md`。
- **下一步（增强项）**：企业画像沉淀（**企业级**，供 M6 技术标/M8 评标调用）、素材完整性体检（缺哪类资质）、面向 M5/M6 的「按条件调取素材」接口。

## M2 模板库
- **目标**：管理商务标/技术标/封面/目录等可复用模板（国标/行业格式）。**企业级**：与素材库性质相同（按企业隔离、落位于 `<软件根>/<企业>/企业级/模板库/`、主要支撑商务标），但实现逻辑不同——管的是模板文件而非原始素材。
- **输入**：历史中标模板、用户提供的范本。
- **输出**：标准化模板文件（docx），含占位符规范。
- **依赖**：M3（格式规范，共享级）。
- **状态**：⏳
- **下一步**：确立模板目录结构与占位符约定。

## M3 知识库
- **目标**：沉淀招投标法规、评分标准库、技术方案素材等**共享知识**（所有企业共用、与企业无关、落位于 `<软件根>/共享资源/知识库/`、主要支撑技术标）。
- **输入**：法规文本、评分标准、历史技术方案等（**企业画像属企业级，归素材库/模板库侧，不在此**）。
- **输出**：可被检索的结构化知识（供 M4/M7/M8 调用）。
- **依赖**：无。
- **状态**：⏳（共享级）
- **下一步**：定义知识条目 schema + 检索接口约定。

## M4 招标文件解析
- **目标**：由 **agent** 解析招标文件，产出两个文本——①**投标要点**（含评标办法：硬性规定防废标 + 评分要点，逐条带原文锚点）；②**素材清单**（对齐 M1 素材库大类/子类，生成前先询问用户是否有特定清单，优先按用户清单核对、无特定要求的素材匹配最适合、缺料标红）。
- **输入**：招标文件（PDF/DOCX/图片；DOCX/TXT/MD 由脚本内置提取，PDF 文本与图片 OCR 由 agent 提取后传入）。
- **输出**：`投标要点_<项目>.md/.json` + `素材清单_<项目>.md/.json`（双份：人读文本 + 机读 JSON）+ `素材对照_<项目>.csv`（已有/缺失/匹配建议，缺料标红）+ `源文件/`（招标文件原件归档）；落位**项目级** `<软件根>/<企业>/项目级/<项目名>/招标解析/`，项目独享资料落同级 `项目资料/`。
- **依赖**：M1 素材库（`query()` 对照取素材）；解析主体为 **agent**（平台无关：可借助各平台专项技能，如 bid-doc-interpreter）。
- **状态**：✅ 已交付（v0.8.1，2026-10-02；需求对齐 v1.3 + 脚本 + 三塔层测试）
- **实现说明**：
  - 需求依据：`references/M4-招标文件解析-需求对齐.md`（v1.3 定稿，用户构思版）。
  - 分工：agent 承担语义解析；脚本只做确定性操作——`scripts/m4_tender/rules.py`（纯逻辑：JSON 结构校验/命名/对照三态/渲染）、`scripts/m4_tender/tender.py`（存储：项目级目录/原件归档/DOCX 提取/双份落盘/素材对照）、`scripts/m4_tender/__init__.py`（CLI：`tender-init/extract/parse/check/show`，薄壳挂载一行）。
  - 产物落位：项目级 `<软件根>/<企业>/项目级/<项目名>/招标解析/`（`源文件/` 原件归档 / 原文 / 投标要点 md+json / 素材清单 md+json / 素材对照 csv）+ 同级 **`项目资料/`**（项目独享资料，`tender-init` 自动创建）；**项目名由 agent 解析招标文件后自动确定**并自动建目录（需求对齐 v1.3）。
  - 对照三态：✅已有 / 🔴缺失·必须（废标风险）/ ⚠️缺失·加分；缺料标红提示。
  - 用法与字段：`references/M4-招标文件解析-操作手册.md`（v1.1，命令速查已回填）。
- **下一步（增强项）**：agent 解析工作流提示词/模板内置于 SKILL.md 引导；素材对照建议字段与 M5 商务标取用接口打通；PDF/图片原文提取的标准通道。

## M5 商务标制作
- **目标**：按模板与解析结果生成商务标文件。
- **输入**：M4 解析结果 + M1 素材 + M2 模板。
- **输出**：商务标 docx（资质/业绩/报价/承诺函等）。
- **依赖**：M1、M2、M4。
- **状态**：⏳
- **下一步**：定义商务标章节映射与自动填充逻辑。

## M6 技术标制作
- **目标**：按评分项与模板生成技术方案。
- **输入**：M4 评分标准 + M1 素材 + M2 模板 + M3 知识。
- **输出**：技术标 docx（方案/组织架构/进度/质量/安全等），去AI味、符合页数。
- **依赖**：M1、M2、M3、M4。
- **状态**：⏳
- **下一步**：评分项→章节映射 + 调用排版/去AI味技能。

## M7 标书检查
- **目标**：商务标+技术标符合性/完整性/废标项体检。
- **输入**：生成的标书 + M4 红线 + M2 模板规范。
- **输出**：问题清单（按严重级）、整改建议、偏离表。
- **依赖**：M2、M4，可调用 `bid-compliance-checker`。
- **状态**：⏳
- **下一步**：定义检查项清单 + 自动校验脚本。

## M8 AI模拟评标
- **目标**：基于评分标准模拟打分，诊断失分点。
- **输入**：M4 评分标准 + 生成的标书 + 企业画像（企业级）。
- **输出**：预估得分、各维度失分诊断、竞争力建议。
- **依赖**：M3、M4、M6。
- **状态**：⏳
- **下一步**：评分模型设计（客观分自动算、主观分按素材证据打分）。

## 建议的实现顺序
M3（共享知识库）→ M1（企业素材库）、M2（企业模板库）→ M4（解析）→ M5、M6（制作）→ M7（检查）→ M8（模拟评标）。
也可按用户当期需求跳跃实现，每完成一处即回填本文件与 SKILL.md 状态。

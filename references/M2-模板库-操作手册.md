# M2 模板库 操作手册

> 版本：v2.0 ｜ 2026-10-19 ｜ 配套需求对齐：references/M2-模板库-需求对齐.md（D1–D25）
> 范围：模板库台账 + CLI 全套；**布局样板范式 v2.0**（模板=版面样板、素材清单驱动）；商务标全流程衔接（§4）

---

## 1. 分工说明（agent / 脚本 / 用户）

| 角色 | 职责 |
|---|---|
| 脚本（tpl-*） | 确定性操作：台账读写（JSON/CSV 双写）、docx 占位符扫描、模板文件登记、按代理机构/采购方式检索、目录对账、概览 |
| agent | 语义判断：占位符登记清单的「说明」列维护、模板归属（代理机构/方式）、是否为新模板/替换旧模板、tpl-sync 结果的取舍 |
| 用户 | 决策：确认导入/登记、删除/覆盖、清单措辞 |

**禁止**：脚本假装看懂占位符含义；agent 绕过脚本直接改台账文件。

## 2. 目录与数据落位

```
<软件根>/<企业>/企业级/模板库/
├── 模板台账.json / 模板台账.csv        ← 权威台账（双份一致，勿手改）
├── <招标代理机构>/                      ← 如：大成工程咨询有限公司
│   ├── 投标/                            ← 模板文件（docx/doc/pdf/txt/md）
│   ├── 采购/
│   └── 询比价/
│       └── 占位符登记清单.md            ← 该机构/方式下全部模板的占位符索引（agent 维护）
```

台账字段：`id / 代理机构 / 方式 / 文件 / 相对路径 / 占位符数 / 图片占位符数 / 登记清单 / 备注 / added_at`

## 3. 标准流程

### 3.1 初始化
```bash
python bidcraft.py --root <软件根> --enterprise <企业> tpl-init
# 幂等；--force 重建为空台账（仅迁移场景，需用户确认）
```

### 3.2 新增模板（外部文件 → 模板库）
```bash
python bidcraft.py tpl-import --file D:/模板/开标一览表.docx \
    --agency 大成工程咨询有限公司 --mode 投标 --note "报价表"
# 自动：复制到 模板库/<代理机构>/<方式>/ + 扫描 docx 占位符 + 写台账
# 非 docx（doc/pdf）自动扫描失败 → 必须由 agent 先读文件给出占位符数：
#   --placeholders N --img-placeholders M
# 目标文件已存在 → 报错（防覆盖，需人工决策）
```

### 3.3 登记库内已有文件（tpl-sync 发现后的补登记）
```bash
python bidcraft.py tpl-sync
#   → "磁盘有但台账缺失（待登记）"列出未登记文件
# 确认归属后逐个登记（不复制）：
python bidcraft.py tpl-import --file <库内文件绝对路径> \
    --agency <代理机构> --mode <方式> --in-place
```

### 3.4 检索 / 概览 / 清单
```bash
python bidcraft.py tpl-list [--agency <代理机构>] [--mode 投标|采购|询比价]
python bidcraft.py tpl-query [--agency ...] [--mode ...] [--keyword 开标一览表]
python bidcraft.py tpl-overview
python bidcraft.py tpl-registry --agency <代理机构> --mode 投标 [--file 开标一览表]
# 全部命令支持 --json（位置可在子命令前或后）供 agent 机读
```

### 3.5 占位符登记清单维护（agent）
- 位置：`模板库/<代理机构>/<方式>/占位符登记清单.md`
- 格式：按模板文件分节（`## 文件名.docx`），每行 `| 序号 | 占位符（{{ 键名 }} / 【图片占位：类别】 / 样板键） | 说明/填充提示 |`
- 触发时机：模板入库/更新后、M5 填充前、M7 检查时引用
- **登记清单不属于台账行**，由 agent 按模板正文逐项核对维护（与 v2.0 母版一致）
- **注/备注类内容不登记占位**（D24）：附表6、附表7 注及全文注/备注均为**动态更新源**——保留源文件原文、不设占位；项目模板制作时依据招标解析的投标文件格式内容更新
- **✅ v2.0（2026-10-19）**：企业模板**重新启用为布局样板母版**（V5 废弃条款作废）——模板只描述每类素材如何排版（`{{ }}` 文字键 + `【图片占位：类别】` + 样板行/页），**禁止硬编码人名/证书名**；放哪些人/证书/数量由**项目素材清单驱动**（未列不生成）。占位符登记清单/模板台账服务于 fill-tpl 填充与 M7 检查。制作规范=`企业级/模板库/_模板制作规范.md` v2.0。

## 4. 商务标全流程中的位置（v2.0 布局样板范式）

```
① 解析招标文件 → ② 素材清单确认（列出 personnel/performance/资质/荣誉/认证等）
→ ③ 企业母版=布局样板（人工制作：固定条款照抄、可变文字 {{ }}、图片【图片占位：类别】、人员/业绩只做样板行/页）
→ ④ 项目模板=母版复制（fill-tpl 从母版深拷贝样板结构，不挖占位不改排版）
→ ⑤ 商务标=fill-tpl 填充（占位索引→样板复制→类别聚合依序消费→未列不生成/缺图披露）
→ ⑥ 校验三道（M7 双通道）+ 人工复核
```
- **M5 取模板一律走 `tpl-query`（台账是唯一权威记录），不直接扫目录**（与 M1 素材库同约定）。
- 详细填充引擎见 `references/M5-项目模板生成-操作手册.md` v4.0 与 `dev/plans/fill-tpl-v2-refactor.md`。

## 5. 对话检查点（不得静默跳过）

- 删除/覆盖/替换模板文件；
- 模板归属（哪个代理机构/哪种方式）不确定时；
- tpl-sync 新增文件的登记取舍；
- tpl-init --force 重建台账。

## 6. 退出码

`0` 成功 / `1` 参数或状态错误（含文件冲突、企业不存在）/ `2` argparse 拒绝（非法 --mode 等）

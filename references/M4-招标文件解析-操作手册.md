# M4 招标文件解析 · 操作手册

> 适用：bidcraft skill（标书匠）· 模块 M4 招标文件解析
> 形态：**skill 驱动 agent**——解析能力由 agent 完成，脚本只做编排与存取
> 对应需求：`references/M4-招标文件解析-需求对齐.md`（v1.1 定稿）
> 版本：初稿（v1.1 工作流定义；脚本命令待实现后回填「命令速查」）

---

## 一、这套东西怎么分工

| 角色 | 负责什么 | 载体 |
|------|----------|------|
| **agent（语义解析）** | 读取招标文件、按模块解析、生成两个文本（投标要点 + 素材清单）、逐条带原文锚点、对照素材库给出匹配建议 | 豆包 / WorkBuddy / hermes / trae work 等 |
| **脚本（确定性）** | 项目级目录存取、原文落盘、双份产物（文本+JSON）落盘、素材库 `query()` 对照、缺料对照表 | `scripts/bidcraft.py` + `scripts/m4_tender/`（待实现） |
| **用户（决策）** | 提供特定清单（可选）、确认对照结果、确认最终素材清单与投标要点 | 对话 |

- **平台无关**：解析工作流只依赖 agent 通用能力（读文档/图片、语义理解、写文件），不依赖任何平台私有能力；PDF/图片 OCR 由各平台 agent 自带能力完成。
- 依赖：**Python 3.8+ 标准库**（脚本侧），无第三方包。

## 二、标准流程（agent 编排，一次一个任务）

> 对应需求 v1.1：招标解析 → 投标要点 + 素材清单 → 素材库取用/补充 → 商务标制作

### 阶段 ①｜定位项目与确认目录

1. 确认企业（`--enterprise`，单企业可省略）。
2. **项目名由 agent 解析招标文件后自动确定**（从招标文件提取项目名称，如「XX安置房项目监理」），不再由用户先给。
3. 脚本用该项目名自动创建/复用项目级目录结构（幂等）：`<软件根>/<企业>/项目级/<项目名>/招标解析/`（含 `源文件/` 子目录）+ **`项目资料/`**（项目独享资料，与招标解析同级）。
   - **对话要点**：项目名自动确定后向用户复述确认；若招标文件未载明项目名，则询问用户。

### 阶段 ②｜读取招标文件（归档原件 + 提取正文）

- 用户上传的招标文件（PDF / DOCX / 图片等）→ `tender-extract --file <原件>` **自动归档**到 `招标解析/源文件/源文件_<项目名>.<ext>`（幂等：同内容重复上传跳过；不同内容报错不覆盖）。
- **DOCX / TXT / MD**：脚本内置提取正文 → `原文_<源名>.txt`。
- **PDF / 图片**：原件同样归档；正文由 agent 提取（OCR / 平台文档解析）后以 `--text-file` 传入 → `原文_<源名>.txt`。
- **对话要点**：原文提取后先核对——页数/字数合理、无乱码缺页，再进入解析。

### 阶段 ③｜agent 解析（核心，语义工作）

agent 按以下模块通读原文并逐条摘录，**每条要点必须带原文锚点**（条款号 / 页码 / 原文摘录），防废标核查时可回看原文：

| 区 | 模块 | 解析内容 |
|----|------|----------|
| 硬性规定区（防废标） | 资格要求 | 资质等级 / 业绩 / 人员（总监、专监、安全监理等）/ 信用 / 财务（如中小企业声明函） |
| | 废标红线 | 资格性 / 符合性 / 响应性 / 否决投标条款 / 其他（围串标、弄虚作假） |
| | 时间节点 | 获取文件、答疑澄清、投标截止、开标、保证金递交、踏勘 |
| | 编制与递交要求 | 格式 / 份数 / 密封 / 装订 / 签字盖章 / 电子文件 |
| 评分要点区（得分导向） | 评标办法与评分标准 | 评标方法、评分项清单（技术/商务/价格分值、得分条件、需提交的证明材料） |
| 其他 | 项目概况 | 项目名称 / 招标人 / 代理 / 地点 / 预算（控制价）/ 资金来源 / 监理范围 |
| | 合同关键条款 | 服务期 / 监理范围 / 付款方式 / 监理费 / 违约责任 |

> **诚实原则**：拿不准的条款标注「待确认」，不臆断；废标红线宁可多列不可漏。

### 阶段 ④｜生成投标要点（产物 A）

- 按「产物 A 模板」（见下）组织为 Markdown 文本，同时生成同内容 JSON（机读，供 M5/M7 调用）。
- **对话要点**：生成后请用户核对硬性规定区（资格/红线/时间/编制），确认无漏项后再定稿。

### 阶段 ⑤｜生成素材清单（产物 B）—— 先问特定清单

1. **生成素材清单前**，先询问用户：**「有没有特定清单提供？」**（可以有，也可以没有）。
   - **有**：优先按用户清单逐项核对素材库（有 / 没有 / 缺部分），并把用户清单项并入素材清单。
   - **没有**：直接从解析出的资格项/评分项推导素材清单。
2. agent 从资格要求与评分标准中推导素材项：**大类/子类（对齐 M1 素材库）+ 用途（对应资格项或评分项）+ 必须/加分 + 来源条款**。
3. **无特定要求的素材项**：在素材库中**匹配最适合的素材**（脚本 `query()` 按大类/子类/关键字检索）。
4. 产出：素材清单（文本+JSON）+ **已有/缺失对照表**（缺硬性素材标红 = 废标风险提示）+ 匹配建议。
5. **对话要点**：对照结果请用户确认——缺料标红项确认是否补充；匹配建议确认是否采纳。

### 阶段 ⑥｜进入商务标制作（M5，后续模块）

素材清单经用户确认后，即作为 M5 商务标的取用依据（按清单逐项取素材填充）。

## 五、对话检查点（不得静默跳过）

1. 建项目目录前：确认**项目名**。
2. 原文提取后：核对**字数/页数、无乱码缺页**。
3. 生成素材清单**前**：询问**是否有特定清单**（有 → 优先核对；没有 → 匹配最适合）。
4. 投标要点定稿前：核对**硬性规定区无漏项**（资格/红线/时间/编制）。
5. 对照结果：**缺料标红项**确认是否补充；**匹配建议**确认是否采纳。

## 六、命令速查（脚本，v0.8.0 已实现）

```bash
python scripts/bidcraft.py [--root <软件根>] [--enterprise <企业>] [--json] <子命令> [参数]
```

| 命令 | 作用 |
|------|------|
| `tender-init --project <项目名>` | 创建/复用项目级目录结构（幂等，项目名禁路径分隔符；项目名由 agent 解析后自动确定）：**`招标解析/`（M4 产物）+ `项目资料/`（项目独享资料）** |
| `tender-extract --project <名> --file <原件> [--text-file <已提取文本>]` | **归档原件**（任意格式 → `源文件/源文件_<项目名>.<ext>`）+ 提取原文：DOCX/TXT/MD 内置；PDF/图片需配 `--text-file`（agent 提取文本） |
| `tender-parse --project <名> --points-md <md> --points-json <json> --list-md <md> --list-json <json>` | 校验并落盘双份产物（投标要点 / 素材清单，文本+JSON；JSON 须按模板含 modules/items，带 BOM 亦可） |
| `tender-check --project <名>` | 素材清单逐项对照素材库 → `素材对照_<名>.csv` + 缺料标红（🔴必缺/⚠️加分缺） |
| `tender-show --project <名> [--what points\|list\|check]` | 人读查看（默认投标要点） |

- 产物落位：`<软件根>/<企业>/项目级/<项目名>/招标解析/`（`源文件/`、原文、投标要点、素材清单、素材对照）；项目独享资料放同级 `项目资料/`。
- 素材对照状态三态：`✅已有 / 🔴缺失·必须（废标风险）/ ⚠️缺失·加分`。
- 退出码：`0` 成功 / `1` 参数或状态错误（无部分失败场景）。

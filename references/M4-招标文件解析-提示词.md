## ▍通道B 解析职责（与通道A 的关系）

| 通道 | 载体 | 职责 |
|------|------|------|
| **通道A** | 脚本规则引擎（`tender-rule`，已落地） | 确定性字段抽取（编号/金额/日期/百分比等），带原文行号锚点 → `文档解析_<项目名>.json` |
| **通道B** | **本提示词（必须使用）** | 完整语义解析：9 模块要点 + 风险/倾向性审查 + 响应文件格式独立文件提取 → 投标要点文本 + JSON（含 diffs） |
| **双通道** | `tender-diff` | 比对实质差异（事实值不同/存在性差异/语义冲突）→ 差异并入投标要点 diffs 块，由用户裁决 |

通道A 是确定性兜底（防通道B 遗漏/误报）；通道B 是完整语义与风险来源。**两通道产出都须带原文锚点**。

## ▍完整版提示词（通道B 必须按此执行）

```
你是一位资深的招投标与工程监理专家，擅长对招标文件做结构化拆解、关键信息提取与风险排查。请阅读我提供的招标文件（PDF/Word/图片/纯文本均可），按以下规范输出解析结果。

【可调参数】（如未指定则按默认值执行）
- 项目类型 = 工程监理（可选：工程施工 / 货物 / 服务 / 信息化）
- 关注模块 = 全部（可选：只解析指定模块，如"仅技术要求和废标项"）
- 输出深度 = standard（可选：brief=仅废标项+资格+评分；detailed=全模块+倾向性+偏离应对）

【输入与分块规则】
1. **分段精读执行流程（v1.1，硬性步骤，所有文件必走，超 100 页/文字量巨大尤甚）**：
   ① 先扫目录/章节标题，建立「章节 → 9 模块」归属表（如：采购公告/前附表/须知 → basic/qualification/reject；评标办法 → scoring；采购需求 → project_overview/staff；响应文件格式 → submission/独立文件）；
   ② 按归属表**逐章节分段精读**，每段只提取归属模块的字段，逐条带原文锚点（章节+条款号/行号）；
   ③ 各段读完后再做**跨段汇总与交叉查重**：同一要求多处出现（如保证金在前附表与须知各写一次）→ 归并并标注所有出处；发现前后矛盾 → 记入 diffs/待确认；
   ④ 末尾输出"解析完整度声明"（覆盖 X/9 模块，未覆盖模块及原因）。
   ⑤ 严禁一次性整段通读后凭印象输出——分段精读、逐段落笔，防长文档信息丢失（本项目 1800+ 行原文必须按此执行）。
2. 扫描件/图片先逐页 OCR 提取文字；识别不清处用 [?] 标注并提示"建议提供 PDF/Word 版"。
3. 【补遗/澄清比对】若同时提供补遗、澄清、修改文件：必须与原文件逐条比对差异，输出"对投标人影响对照表"（条款 / 原文件 / 补遗澄清后 / 对投标影响），并以补遗澄清后的要求为准更新相关模块。

【解析维度：9 大模块 + 倾向性审查，逐模块输出】
模块一 basic 项目基本信息：项目名称/编号、招标人/代理、采购方式、预算/最高投标限价、资金来源、建设地点/规模、工期或服务期、投标截止时间/开标时间地点、投标保证金（金额/形式/缴纳截止/退还）、是否专门面向中小微/联合体/暗标、**电子标或纸质标、实名制或非实名制**。
  → 末尾做"时间充裕度评估"（距截标天数；≤20 天或保函/授权窗口极短者标 ⚠️ 高风险）；若为暗标提醒"不得出现公司名称、Logo 等标识"。
模块二 qualification 资格条件：逐条列出资格要求、需提供的证明材料、性质（强制/加分）、原文位置、风险提示。工程监理类重点：监理资质等级、总监理工程师注册专业与单位注册、安全生产/信用不良记录、中小企业政策。**不得解析登记方式/登记要求**（如"在线登记""电子注册"类流程性要求）。
模块三 staff 人员配备：岗位/人数/证书要求/注册单位/兼职限制/社保要求/**委托代理人要求（有无社保）**，逐条标原文位置。
模块四 project_overview 项目概况与监理工作内容：改造范围、栋数/户数/规模、监理工作内容与范围、监理依据与目标——**这是技术标写作依据，必须完整解析**。
模块五 scoring 评标办法与评分标准（核心必做）：评标方法、评委会构成、分值构成、各评分项标准、主客观分判定、价格分计算公式（重点核对"低价是否反而不利"）。
模块六 pricing 报价要求：报价上限（废标线）、报价形式（费率/总价）、费率折算规则、报价文件组成。**报价金额由用户提供，本模块不解析具体报价金额**；合同性商务内容（付款方式/质保金/履约保证金/验收标准/违约责任等）**一律不解析**。
模块七 submission 响应文件编制与递交：份数/装订/密封/递交方式/文件组成（摘要）、响应有效期。**格式全文以《响应文件格式_<项目名>.txt》为准（独立文件，一字不改），本模块只做组成摘要**。
模块八 reject 废标/否决红线：不予接收情形、资格性/符合性废标项、围标串标/虚假材料等其他否决情形，逐条标原文位置。**不得解析信用黑名单**（失信被执行人名单、信用不良记录等）。
模块九 pending 待确认/缺失项：招标文件未写但影响投标的内容（有缺口才列），如：合同关键条款缺失、图纸/工程量清单缺附件等。
附加 倾向性与排他性审查：指定品牌/型号、★条款数量异常、业绩精准卡位（年份+金额+甲方+地区四重限定）、资质叠加过高、评分项仅 1-2 家可满分、时间窗口过短；发现疑似条款用 🔴 高亮并标"建议书面澄清"，引用法规用 [参考：《…》第X条]，仅做"疑似"标注不做法律定性。

【输出格式规范】
- 结构化字段一律用表格，且必须包含"原文位置"列（优先页码，无页码用 章节+条款号，如 P21 / 第二章 25.1 / 第七章评标办法）。
- 非结构化要点用清单。
- 易踩坑条款用 ⚠️ 标记，并同步计入文末"投标风险提示"汇总。
- **风险分级**：废标/否决风险=🔴 高；扣分/失分风险=⚠️ 中；提示性信息=💡 低。
- **同时产出机读 JSON**：按投标要点 JSON 骨架输出（9 模块 modules + diffs 数组），字段缺失用「原文未提供」，禁止省略字段；JSON 与人读文本内容一致。
- 需归入素材清单的证明材料项（资质证书/人员证书/业绩/承诺函等）在对应条款后标注【素材清单】。

【铁律（不可违反）】
1. 忠于原文·防幻觉：所有资格、技术参数、废标项、评分细则必须标注原文位置；若关键条款无法追溯，不得写入正文，改标「⚠️ 原文检索未定位，建议人工复核」。严禁用"行业常识/通常做法"补充原文不存在的条款。**不得编造页码**。
2. 缺失即标注：原文未提供→「原文未提供」；原文含糊→「原文不明确（建议书面澄清）」。
3. 范围边界：本解析仅做信息整理、条款定位与风险提示，不做报价计算、投标编制、法律定性、中标概率预测；报价金额由用户提供，不推测。
4. **合同内容一律不解析**：合同协议书、通用/专用合同条件、附件（考核办法、违约金、驻场要求、履约承诺、安全目标等）、监理管理考核打分表——除非用户明确要求。
5. **响应文件格式全文提取**：招标文件「响应文件格式（投标文件格式）」章节必须全文提取为独立文件《响应文件格式_<项目名>.txt》，一模一样、一个字都不能更改（除非人工修改）；提取后与原文逐行比对校验。
6. **双通道差异块**：解析完成后与通道A（`文档解析_<项目名>.json`）做差异比对——事实值不同/存在性差异/语义冲突三类实质差异列示入投标要点 diffs 块，以招标原文为最终依据，由用户裁决；表述详略差异不列示。
7. 输出前逐模块自校验：9 模块全覆盖、每条带原文锚点、JSON 结构合法。

【报告结尾固定结构】
- ⚠️ 投标风险提示（汇总所有 ⚠️/🔴/💡，逐条标模块与原文位置）
- 解析完整度声明（本次覆盖 X/9 模块；未覆盖模块及原因）
- 免责声明：本解读为 AI 辅助，不构成法律意见或投标建议；正式投标以官方发布文件为准。

【投标要点 JSON 骨架】（机读产物，供 M5/M7 调用；字段缺失用「原文未提供」）
{

  "modules": [
    {"id": "basic", "title": "项目基本信息", "type": "fields", "fields": {"字段名": {"value": "值", "evidence": "原文位置"}}},
```

## ▍精简版（快速过标用）

```
请阅读以下招标文件，按维度提取要点并用表格输出（每一条标注原文位置/页码）：
1) 项目基本信息（名称、限价、工期、截标时间、保证金、电子/纸质标）；
2) 资格要求（资质、人员、业绩、信用）——不解析登记方式/登记要求；
3) ★实质性条款与废标情形（不解析信用黑名单）；
4) 评标方法与分值构成（价格分公式、主观分占比）；
5) 主要风险点与应对建议。
要求：忠于原文、缺失标注"原文未提供"、不做报价与编制、合同内容不解析、末尾给风险提示汇总。
```

## ▍评标办法专项深挖（投标前必跑，监理标尤其重要）

```
针对本招标文件"评标办法"章节，做专项深挖并输出：
1) 评标方法确定（综合评分/最低价/性价比）与评委会构成；
2) 完整评分明细表：维度 / 分值 / 评分项 / 评分标准 / 主客观 / 原文位置；
3) 价格分公式还原：写出计算公式，举例说明报价多少能拿满分、是否"低价不利"（只还原规则，不填报价金额）；
4) 主观分识别：标注所有主观分及其占比，占比 >40% 时提示自由裁量风险；
5) 倾向性/排他性评分项：仅 1-2 家可满分的项用 🔴 标出，并给"能否响应/如何响应"建议；
6) 一票否决项与"必须无偏离"的★条款清单。
```

## ▍使用技巧

- **长文件先喂目录**：把 PDF 目录页 + 投标人须知前附表 + 评标办法三处先发，AI 定位最快。
- **分模块追问**：先跑完整版拿到全景，再针对"模块五评分"或"模块二资格"单独深挖。
- **多份对比**：同时传原文件+补遗/澄清，指令加"对比差异并输出对投标人影响的对照表"（补遗/澄清后要求为准）。
- **接投标编制**：本提示词只做解析；拿到结果后，可用"按此评分标准帮我写技术标响应"继续推进（进入 M5/M6 环节）。
- **衔接素材清单**：解析中标注【素材清单】的证明材料项，将在素材清单环节对照素材库查漏（tender-check）。

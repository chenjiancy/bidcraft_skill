## 一、目标与形态

- **目标**：解析招标文件，产出**两个文本**：
  1. **投标要点文本**（按解析要点/模块组织，含评标办法）——用途：①掌握招标文件**硬性规定、避免废标**；②掌握**评分要点**。
  2. **素材清单文本**——用途：①从素材库**提取已有素材**；②提示**补充缺失素材**；③作为**商务标制作的基础**（商务标要用的素材）。
- **形态**：两个 Markdown 文本（人读主产物）+ 各自**机读 JSON**（双份数据，供 M5 商务标 / M7 标书检查机器调用）。同一内容双写，文本与 JSON 一致。
- **解析主体**：**agent**（多模态读取 PDF/DOCX/图片 OCR，语义理解、归类、抽取）。
- **脚本职责**（确定性操作）：项目级目录存取、原文落盘、两个文本+JSON 落盘、素材清单与素材库 `query()` 对照、缺料对照表/标红提示。
- **用户职责**：决策（是否有特定清单、确认对照结果、确认最终清单）。
- **诚实原则**：未确认项不得直接用于 M5/M6/M7；缺硬性素材必须标红提示（废标风险）。

## 二、输出产物定义

### 产物 A：投标要点文本（`投标要点_<项目名>.md` + `投标要点_<项目名>.json`）
按模块组织，**每条要点带原文锚点**（条款号/页码/原文摘录，行业共识：可追溯才可防废标）：

- **硬性规定区（防废标）**
  - m3 资格要求：资质等级 / 业绩 / 人员（总监、专监、安全监理等）/ 信用 / 财务（如中小企业声明函）
  - m5 废标红线：资格性 / 符合性 / 响应性 / 否决投标条款 / 其他（围串标、弄虚作假）
  - m2 时间节点：获取文件、答疑澄清、投标截止、开标、保证金递交、踏勘
  - m7 编制与递交要求：格式 / 份数 / 密封 / 装订 / 签字盖章 / 电子文件
- **评分要点区（得分导向）**
  - m4 评标办法与评分标准：评标方法、评分项清单（技术/商务/价格分值、得分条件、需提交的证明材料）
- **其他**
  - m1 项目概况：项目名称 / 招标人 / 代理 / 地点 / 预算（控制价）/ 资金来源 / 监理范围
  - m6 合同关键条款：服务期 / 监理范围 / 付款方式 / 监理费 / 违约责任

### 产物 B：素材清单文本（`素材清单_<项目名>.md` + `素材清单_<项目名>.json`）

- 每条素材字段：**素材大类/子类（对齐 M1 素材库：资质/人员/业绩/荣誉/财务/企业介绍）＋用途（对应资格项或评分项，附原文）＋必须/加分＋来源条款＋对照结果**。
- **生成流程（关键，用户确认）**：
  1. agent 解析招标文件；
  2. **生成素材清单前**，先询问用户：**是否有特定清单提供**（可以有，也可以没有）；
  3. **有**：优先按用户给的清单逐项核对素材库（有 / 没有 / 缺部分）；
  4. **无**（或无特定要求的素材项）：从素材库**匹配最适合的素材**；
  5. 产出素材清单 + **已有/缺失对照表**（缺料标红、废标风险提示）+ 匹配建议。

## 一、目标与形态

- **目标**：解析招标文件，产出**投标要点**（人读+机读）、**响应文件格式独立文件**（全文原文）、**素材清单**（人读+机读）：
  1. **投标要点文本**（按 9 模块组织，每条带原文锚点）——用途：①掌握招标文件**硬性规定、避免废标**；②掌握**评分要点**；③提供项目概况与监理工作内容（技术标写作依据）。
  2. **响应文件格式独立文件**（`响应文件格式_<项目名>.txt`）——招标文件「响应文件/投标文件格式」章节**全文提取，一字不改**（除非人工修改）；它是**内容地基**（标书要呈现的内容骨架），**不是格式排版地基**（格式排版由企业模板控制）；供 M2 项目模板生成时与企业模板做**内容校验**。
  3. **素材清单文本**——用途：①从素材库**提取已有素材**；②提示**补充缺失素材**；③作为**商务标制作的基础**。
- **形态**：投标要点/素材清单 = Markdown 文本（人读主产物）+ 各自**机读 JSON**（双份数据，供 M5 商务标 / M7 标书检查机器调用）；响应文件格式 = 纯文本独立文件（原文，无 JSON）。
- **解析主体（双通道，v2.1）**：
  - **通道A 文档解析（确定性）**：脚本规则引擎——原文提取、表格结构（表头/行列）、**关键事实字段**（项目编号/金额/日期/人数/百分比/资质要求/截止时间等）、条款锚点、响应文件格式全文；适用"确定性要素"（资质、盖章、截止时间等格式固定、表述规范的字段）。
  - **通道B agent 语义解析（语义性）**：agent 按 9 模块语义理解、归类、抽取，解读评分规则/认定口径/废标红线归纳/待确认项；适用"开放性要素"（评分标准、业绩要求等表述多变的字段）。
  - **双通道互补**：通道A 快、准、可调试；通道B 能理解开放性内容；两者独立产出，互不覆盖。
- **脚本职责**（确定性操作）：项目级目录存取、原文落盘、双份产物落盘、素材清单与素材库 `query()` 对照、缺料对照表/标红提示、**双通道差异比对（确定性比对）**。
- **用户职责**：决策（解析结果确认、双通道差异裁决、是否有素材清单、确认对照结果、确认最终素材清单）。
- **诚实原则**：未确认项不得直接用于 M5/M6/M7；缺硬性素材必须标红提示（废标风险）；解析不了或招标文件未写的内容列入「待确认/缺失项」模块，不假装完整。

## 二、输出产物定义

### 产物 A：投标要点文本（`投标要点_<项目名>.md` + `投标要点_<项目名>.json`）

**解析内容框架 v5（9 模块，2026-10-07 用户逐项确认固定）**：

| # | 模块 | 解析内容 | 备注 |
|---|------|----------|------|
| 1 | 项目基本信息 | 名称/编号/采购人/代理机构/预算限价/资金来源/服务期/**投标截止日期**/**电子标或纸质标**/**实名制或非实名制投标**/开标时间地点/投标有效期/保证金 | 电子/纸质、实名/非实名不影响标书制作，但有助于标书制作人员了解投标要求 |
| 2 | 资格条件 | 资质等级、拟派总监要求、联合体要求 | **不解析**登记方式/登记要求（标书制作用不到） |
| 3 | 人员配备 | 岗位/人数/证书类型/注册单位要求/兼职限制/社保要求/**委托代理人要求（特别是有无社保要求）** | |
| 4 | 项目概况与监理工作内容 | 改造范围、栋数户数、监理工作内容/范围 | **技术标（监理大纲）写作依据，必须解析** |
| 5 | 评分办法 | 总分构成、每个评分项的分值/计分规则/认定口径（如业绩以合同签订时间认定） | |
| 6 | 报价要求 | **只解析报价规则**：上限（废标线）、报价形式、费率折算规则 | **报价金额由用户提供**，不解析、不列缺失 |
| 7 | 响应文件编制与递交 | 份数/装订/密封/递交时间地点方式/文件组成（摘要） | 格式全文见独立文件 |
| 8 | 废标/否决红线 | 不予接收情形、初审不通过项、流标条件 | **不解析**信用黑名单（标书制作用不到） |
| 9 | 待确认/缺失项 | 招标文件未写明但影响投标决策或标书编制的信息 | 机制保留，有缺口才列；报价金额不属于此列（用户提供） |

**不解析（除非用户明确要求）**：**合同内容**——合同协议书、通用/专用合同条件、附件（考核办法、违约金、驻场要求、履约承诺、安全目标等）、监理管理考核打分表；商务标、技术标均不引用其内容。合同内容是中标后才生效的执行条款，不影响"投不投、怎么投、报多少价"。

### 双通道解析差异（v2.1，投标要点内置校验块）

- **实质差异判定标准**（可操作定义，非实质差异不列示）：
  1. **事实值不同**：同一解析项两通道取值不同（项目编号/金额/日期/人数/百分比/资质等级等）；
  2. **存在性差异**：一方解析出、另一方遗漏的关键条款/评分项/废标红线；
  3. **语义冲突**：两通道对同一要求解读矛盾（如"前附表不采用保证金 vs 投标函承诺递交担保"）。
  - 表述详略、措辞不同但含义一致 → **不列示**。
- **列示载体**：投标要点新增「双通道解析差异」块（校验层，独立于 9 模块）；每条差异字段：解析项｜通道A文档解析值（出处）｜通道B语义解析值（出处）｜差异类型｜待用户裁决；JSON 同步含 `diffs` 数组。
- **裁决**：差异随投标要点展示，**并入闸门①由用户一并裁决**（不新增确认闸门）；裁决以原文为最终依据。
- **当前能力现状**：通道B（agent 语义解析）已就绪；通道A 目前只有原文提取（tender-extract），**结构化字段抽取/表格解析（规则引擎）未实现**——列入路线图，开发按用户指令推进。

### 产物 A2：响应文件格式独立文件（`响应文件格式_<项目名>.txt`）

- 招标文件「响应文件格式（投标文件格式）」章节（本项目为第七章，含封面/开标一览表/投标函及投标函附录/法人代表资格证明/授权委托书/监理管理文件目录/资格证明及辅助资料表 附表1-10/承诺函等）**全文提取**，**一模一样、一个字都不能更改**（除非人工修改，很重要）。
- 定位：**内容地基**——项目模板生成（M2）和商务标制作时的**内容校验基准**；**格式、排版等由企业模板控制**，本文件不参与排版，也不被商务标/技术标正文直接"套格式"。
- 落位：`招标解析/响应文件格式_<项目名>.txt`，M4 标准产物之一。

### 产物 B：素材清单文本（`素材清单_<项目名>.md` + `素材清单_<项目名>.json`）

- 每条素材字段：**素材大类/子类（对齐 M1 素材库：资质/人员/业绩/荣誉/财务/企业介绍）＋用途（对应资格项或评分项，附原文）＋必须/加分＋来源条款＋对照结果**。

## 三、流程（v2.1，双通道解析 + 用户确认后进入下一步，一次一个任务）

```
① tender-init / tender-extract：归档原件 + 提取原文（项目名由 agent 解析后自动确定）
② 双通道解析：
   通道A 文档解析（脚本规则引擎）：原文/表格结构/关键事实字段/条款锚点/响应文件格式全文
   通道B agent 语义解析：按 9 模块生成投标要点（逐条带原文锚点）
③ 双通道差异比对 → 实质差异（事实值不同/存在性差异/语义冲突）列示为
   「双通道解析差异」块（并入投标要点；非实质差异不列示）
④ 展示投标要点（含差异块）给用户核对 → 用户确认解析完整、正确并裁决差异 ← 必须停在此处
⑤ 询问用户：是否有素材清单上传？（两种情况）
   情况1：用户上传素材清单 → 结合用户清单查询素材库（用户指定的直接查询；
          用户未指定但项目需要的素材，查询素材库后推荐给用户）
   情况2：用户未上传 → 直接查询素材库，匹配最适合的素材推荐给用户
⑥ 产出素材清单（文本+JSON）+ 已有/缺失对照表（缺料标红、废标风险提示）
⑦ 待用户确认素材清单 → 进入下一步（M2 项目模板 / M5 商务标）
```

- **流程铁律（v2.1，见模块开发规范 §二.9）**：需求先复述对齐 → 用户确认 → 联网查建议 → 执行。
- **解析确认闸门（步骤④）**：投标要点（含双通道差异）必须先经用户确认完整、正确，才能进入素材清单环节；未确认不得静默推进。
- **素材清单确认闸门（步骤⑦）**：素材清单必须经用户确认后才能进入下一步。
- 素材对照状态三态：`✅已有 / 🔴缺失·必须（废标风险）/ ⚠️缺失·加分`。

## 四、数据落位（已确认）

- **项目级**：`<软件根>/<企业>/项目级/<项目名>/`；**项目名由 agent 解析招标文件后自动确定**并自动创建子目录。
- 项目级目录结构（由 `tender-init` 自动创建，幂等）：
  - `招标解析/`——M4 解析产物：`源文件/源文件_<项目名>.<ext>`（原件归档）、`原文_<源名>.txt`、`响应文件格式_<项目名>.txt`（全文原文，一字不改）、`投标要点_<项目名>.md/.json`、`素材清单_<项目名>.md/.json`、`素材对照_<项目名>.csv`（已有/缺失/建议，人读）。
  - `项目资料/`——**项目独享资料**（业主往来文件、现场资料、内部参考资料等与解析无关的项目资料），与 `招标解析/` 同级。

## 五、文本提取策略（沿用 v1.0 默认）

- 脚本内置 DOCX（标准库 zip+xml）/ TXT / MD 提取；PDF 文本与图片 OCR 由 agent 提取后传入。
- 不引入第三方解析库（依赖最小化硬约定）。
- 注意：`.doc`（老格式）脚本不支持，需 agent 用 Word COM 转文本（GBK→UTF-8）后以 `--text-file` 传入（已在和县2026老旧小区项目验证）。

# M6 模板设计器 · 数据模型（P0）—— template.json（schema `m6.template/v1`）

> 版本：v0.1 · 2026-10-23 · 落地：`scripts/m6_tech/tpl_design.py` + `tpl-design` 命令
>
> 一句话：**模板不是 docx 母版，而是一张"装配单"**——文档结构编排 + 样式引用 + 占位符绑定 + 规则，
> 全部沉淀为一份可校验、可 diff、可持久化的 JSON；docx 只是渲染产物。
> 这与 M2 商务标"Word 母版照抄"互补不冲突：M2 走原文照抄，技术标类自由编排场景从写死代码升级为可设计数据。

---

## 1. 文件位置与用途

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 模板描述目录 | `共享资源/技术标风格/模板/` | 全部 `*.json` 即模板库（素材库根或其父目录下均可见） |
| 示例模板 | `共享资源/技术标风格/模板/示例-标准技术标.json` | 权威样例；与 `tpl_design.TEMPLATE_EXAMPLE` 保持逐字段一致 |
| 校验/派生/命令 | `scripts/m6_tech/tpl_design.py` | P0 全部逻辑（无 UI 完整可用） |
| 命令入口 | `scripts/bidcraft.py tpl-design ...` | list / show / validate / apply / specimen |
| 样式值域来源 | `共享资源/技术标风格/layout-presets.json` | styleRef 十五组 id 必须取自该文件（`tech-layout --list` 同源） |
| 单测 | `tests/unit/test_m6_template.py` | 32 例：结构/值域/占位符/规则/暗标派生/命令 |

## 2. 顶层结构

```json
{
  "schema": "m6.template/v1",          // 必填，标识数据模型版本
  "version": "0.1",                    // 模板自身版本（自由）
  "updated": "2026-10-23",             // 更新日期
  "name": "示例：标准技术标",           // 必填，模板用途说明
  "description": "……",                 // 可选，补充说明
  "structure": [ … ],                  // 必填，文档部件编排（见 §3）
  "styleRef": { … },                   // 样式引用，十五组 id（见 §4）
  "placeholders": { … },               // 占位符绑定（见 §5）
  "rules": { … },                      // 规则（见 §6）
  "provenance": { … }                  // 来源留痕：basedOn / author / created / note
}
```

## 3. structure——部件编排

部件清单与版面设计器预览的文档段一一对应：

| part | 名称 | P0 默认 pageMode | 必选 | 约束 |
| --- | --- | --- | --- | --- |
| `cover` | 封面 | `single` | **必选** | 必须第一个出现 |
| `colophon` | 扉页 | `single` | 可选 | 在 toc/body 之前；真实成稿可由渲染层决定是否输出 |
| `toc` | 目录 | `single` | 可选 | 在 body 之前 |
| `body` | 正文 | `flow` | **必选** | 在 cover/colophon/toc 之后 |
| `closing` | 结尾 | `single` | 可选 | 必须最后一个出现 |

- 每类部件**至多出现一次**（P0）。
- `pageMode ∈ {"single", "flow"}`：单页部件（封面/扉页/目录/结尾）与流式部件（正文）。
- `optional: true` 仅表示"默认可省略"，渲染时由规则/招标条款决定是否输出（扉页、结尾）。

示例：

```json
"structure": [
  { "part": "cover", "pageMode": "single" },
  { "part": "colophon", "pageMode": "single", "optional": true },
  { "part": "toc", "pageMode": "single" },
  { "part": "body", "pageMode": "flow" },
  { "part": "closing", "pageMode": "single", "optional": true }
]
```

## 4. styleRef——样式引用（十五组，id 必须取自 layout-presets.json）

```json
"styleRef": {
  "preset": "single-column",     "palette": "deep-indigo",
  "cover": "full-block",         "decoration": "standard",
  "font": "gov-gongwen",         "imageRatio": "mid",
  "imageRule": "hybrid",         "imageLayout": "split-h",
  "pageSetup": "p1-standard-a4", "headingSystem": "h1-gbt-arabic",
  "tocStyle": "t1-jianyu-auto",  "tableStyle": "tb1-three-line",
  "captionSystem": "c2-cy-chapter", "paragraphStyle": "pa7-jianyu-15",
  "headerFooter": "hf1-classic-enterprise"
}
```

- **十五组键名固定**：`preset / palette / cover / decoration / font / imageRatio / imageRule / imageLayout /
  pageSetup / headingSystem / tocStyle / tableStyle / captionSystem / paragraphStyle / headerFooter`。
- 每个键的值必须落在 `layout-presets.json` 对应组的 `id` 集合内（校验器逐一比对）；
- **允许缺省**：未写的键自动回退 `sources.DEFAULT_LAYOUT` 的默认值（"缺省键回默认"），便于最小模板。

## 5. placeholders——占位符绑定

键名规范：小写字母开头，仅 `a-z 0-9 _`，≤32 字符（与 docxtpl 的 `{{ }}` 风格一致）。

值规范二选一：

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 文字占位 | `{{ 键名 }}`（键名同键规范） | `"enterprise_name": "{{ enterprise_name }}"` |
| 图片占位 | `【图片占位：类别】` | `"site_photo": "【图片占位：施工现场】"` |

## 6. rules——规则

P0 识别键：

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `bidMode` | `明标` / `暗标`（`rules.BID_MODES`） | 驱动暗标派生（见 §7）；非法值报错 |
| `darkFontSafe` | bool | 明标模板兼容字段，暗标时恒为真 |
| `coverUnderlay` / `pageBreak` / `tablesOnePage` | bool | 兼容/扩展位，P0 校验不强制 |
| 未知键 | — | 仅提示（warn），不阻塞 |

## 7. 暗标派生（确定性规则，无人工二选一）

`rules.bidMode == "暗标"` 时，派生逻辑（`dark_derived`，id 以 layout-presets.json 实际预设为准）：

| 组 | 铁律 | 不合规时 |
| --- | --- | --- |
| `font` | 强制 `dark-safe` | 报错（合规校验）；派生时强制替换并记 notes |
| `imageRule` | 二选一：`dark-safe-img`（暗标安全）/ `no-source`（无图源） | 报错；派生时安全降级 `no-source` 并记 notes |
| `headerFooter` | 二选一：`hf9-dark-none`（无页眉页脚）/ `hf10-dark-page-only`（仅页码） | 报错；派生时安全降级 `hf9-dark-none` 并记 notes |
| 微观六组 | `pageSetup / headingSystem / tocStyle / tableStyle / captionSystem / paragraphStyle` 按招标条款自动注入，**不开放选择** | styleRef 显式指定时仅提示（info），派生值回默认 |

暗标校验失败即拒绝落盘/出样张（err 级），确保暗标铁律不可绕过。

## 8. 命令用法（无 UI 完整可用）

```text
python scripts/bidcraft.py tpl-design --list                          # 模板清单 + 校验状态
python scripts/bidcraft.py tpl-design --show <file>                    # 概览 + 校验 + 暗标派生后 15 组样式
python scripts/bidcraft.py tpl-design --validate <file>                # 只校验，输出问题清单（--json 结构化）
python scripts/bidcraft.py tpl-design --apply <file> --confirm         # 校验→落盘登记→写后回读校验（防覆盖）
python scripts/bidcraft.py tpl-design --specimen <file>                # 按模板全映射出样张 docx（P1）
python scripts/bidcraft.py tpl-design --specimen <file> --fill "k=v;…" # 占位符填充（缺省键自动注入）
python scripts/bidcraft.py tpl-design --specimen <file> --project <项目>  # 走真实项目导出成稿
python scripts/bidcraft.py tech-export --project <项目> --template <file> # 模板驱动导出成稿（成稿入口）
python scripts/bidcraft.py tech-export --project <项目> --template <file> --fill "k=v;…" --override "palette=…"
python scripts/bidcraft.py tpl-design --list --json                    # 全部命令支持 --json 机读输出
```

- `--apply` 未带 `--confirm` 时 dry-run（只校验不写盘）；目标同名存在时拒绝覆盖。
- **P1 模板全映射**（specimen 与 tech-export --template 同引擎）：
  - `structure` 决定部件渲染顺序（封面→扉页→目录→正文→结尾，可选部件按模板声明）；
  - `styleRef` 十五组全部生效（派生 layout 覆盖章节树 layout，`--override` 仍最高）；
  - `placeholders` 由 `--fill` 填充（`enterprise_name`/`project_name`/`bid_date` 缺省自动注入；未提供键保留原文）；
  - `rules.bidMode=暗标` 走暗标铁律（合规模板直接导出暗标稿，不合规拒绝导出）。
- 模板校验失败即拒绝落盘/出样张/导出（err 级），暗标铁律不可绕过。

## 10. P2 部件库（schema `m6.part/v1`）—— docx 母版拆解回流

### 10.1 干什么用
把一本 docx 标书（商务标母版 / 技术标旧稿 / 历史成稿）"拆零件"：识别封面段、目录段、
正文样式、结尾段，把企业名/项目名/日期等**内容**参数化为 `{{ enterprise_name }}` /
`{{ project_name }}` / `{{ bid_date }}` 占位，只保留**版式**，输出部件 JSON 落盘
`共享资源/技术标风格/部件库/`。之后 M6 模板 JSON 的 structure 项可用 `partRef: "部件名"`
引用——导出引擎按部件渲染（版式来自母版、内容由 `--fill`/项目数据填充）。

拆解**对商务标、技术标 docx 均有效**（只认 docx，不认标书类型）；当前落地路径是
"商务标母版 → 部件库 → 技术标模板复用"。铁律不变：
- 只拆版式、不拆内容（D25 内容校验铁律：招标原文一字不改，拆解只提取格式）；
- 来源必须是用户自己的、经人工确认的（D26：脱敏 → 参数化 → 试生成闸门）。

### 10.2 部件 JSON（m6.part/v1）
```json
{
  "schema": "m6.part/v1",
  "source": "示例-商务标母版.docx",
  "name": "示例-商务标母版",
  "parts": {
    "cover": {
      "paragraphs": [
        {"text": "{{ project_name }}", "style": {"east": "仿宋", "size": 26, "bold": false, "align": "center"}},
        {"text": "投标文件（技术标）", "style": {"east": "仿宋", "size": 16, "bold": false, "align": "center"}},
        {"text": "{{ enterprise_name }}", "style": {"east": "仿宋", "size": 14, "bold": false, "align": "center"}},
        {"text": "{{ bid_date }}", "style": {"east": "仿宋", "size": 12, "bold": false, "align": "center"}}
      ],
      "pageBreak": true
    },
    "colophon": null,
    "toc": {"title": "目　录", "style": {"east": "黑体", "size": 16, "bold": true, "align": "center"}, "pageBreak": true},
    "body": {"font": {"size": 12, "east": "仿宋"}, "headingSizes": {}},
    "closing": {"paragraphs": [{"text": "（以下无正文）", "style": {"east": "仿宋", "size": 12, "bold": false, "align": "left"}}]}
  }
}
```
- `colophon`（扉页）拆解器暂不自动切分（置 null，人工补充）——启发式可靠识别 cover/toc/body/closing；
- `paragraphs[].text` 是**文本模板**：含占位符时导出按 `--fill` 填充，未提供键保留原文；
- 结构识别关键词：toc=「目　录」段落；closing=含"以下无正文"段落（倒序查找）；
  cover=toc 前段落（toc 缺失时取开头 1/3）；body=cover 后至 closing 前统计字体/字号众数。

### 10.3 模板引用部件（partRef）
structure 项可加可选 `partRef`（部件名或 部件文件名.json）：
```json
{"part": "cover", "pageMode": "single", "partRef": "示例-商务标母版"}
```
- 校验：`partRef` 引用的部件必须存在于部件库（tpl-part --list），引用不存在 → err 拒绝落盘/出样张/导出；
- 渲染：导出时 cover/colophon/closing 若有 `partRef` → 按部件版式渲染（`_render_part`：逐段文本模板 + 占位符填充 + 样式应用 + pageBreak）；无 → 内置渲染器；
- `body` 部件（正文样式基线）暂由 styleRef 驱动（部件库的 body 段保留作未来基线对照）。

### 10.4 命令（tpl-part，无 UI 完整可用）
```text
python scripts/bidcraft.py tpl-part --list                        # 部件清单（默认行为）
python scripts/bidcraft.py tpl-part --show <部件名>               # 展示部件内容（段落/样式）
python scripts/bidcraft.py tpl-part --scan <母版.docx>            # 拆解预览（dry-run，未写盘）
python scripts/bidcraft.py tpl-part --scan <母版.docx> --project <项目>   # 项目名参数化
python scripts/bidcraft.py tpl-part --scan <母版.docx> --confirm  # 确认落盘部件库（防覆盖 + 写后回读）
python scripts/bidcraft.py tpl-part --list --json                 # --json 机读输出
```
- `--scan` 不带 `--confirm` 只预览（企业名取全局 `--enterprise`，日期自动参数化）；
- 落盘目录固定为素材库根的 `共享资源/技术标风格/部件库`（读时有仓库兜底，写不越界）；
- 同名部件存在时拒绝覆盖（防覆盖闸门）。

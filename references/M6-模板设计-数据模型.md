# M6 模板设计器 · 数据模型（P0）—— template.json（schema `m6.template/v1`）

> 版本：v0.1 · 2026-10-23 · 落地：`scripts/m6_tech/tpl_design.py` + `tpl-design` 命令
>
> 一句话：**模板不是 docx 母版，而是一张"装配单"**——文档结构编排 + 样式引用 + 占位符绑定 + 规则，
> 全部沉淀为一份可校验、可 diff、可持久化的 JSON；docx 只是渲染产物。
> 这与 M2 商务标"Word 母版照抄"互补不冲突：M2 走原文照抄，技术标类自由编排场景从写死代码升级为可设计数据。

---

## 1. 文件位置与用途

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 模板描述目录 | `共享资源/技术标风格/模板/` | 全部 `*.json` 即模板库（素材库根或其父目录下均可见） |
| 示例模板 | `共享资源/技术标风格/模板/示例-标准技术标.json` | 权威样例；与 `tpl_design.TEMPLATE_EXAMPLE` 保持逐字段一致 |

| 样式值域来源 | `共享资源/技术标风格/layout-presets.json` | styleRef 十五组 id 必须取自该文件（`tech-layout --list` 同源） |
| 单测 | `tests/unit/test_m6_template.py` | 32 例：结构/值域/占位符/规则/暗标派生/命令 |

## 2. 顶层结构

```json
{
  "schema": "m6.template/v1",          // 必填，标识数据模型版本
  "version": "0.1",                    // 模板自身版本（自由）
  "updated": "2026-10-23",             // 更新日期
  "name": "示例：标准技术标",           // 必填，模板用途说明
  "description": "……",                 // 可选，补充说明
  "structure": [ … ],                  // 必填，文档部件编排（见 §3）
  "styleRef": { … },                   // 样式引用，十五组 id（见 §4）
  "placeholders": { … },               // 占位符绑定（见 §5）
  "rules": { … },                      // 规则（见 §6）
  "provenance": { … }                  // 来源留痕：basedOn / author / created / note
}
```

## 3. structure——部件编排

部件清单与版面设计器预览的文档段一一对应：

| part | 名称 | P0 默认 pageMode | 必选 | 约束 |
| --- | --- | --- | --- | --- |
| `cover` | 封面 | `single` | **必选** | 必须第一个出现 |
| `colophon` | 扉页 | `single` | 可选 | 在 toc/body 之前；真实成稿可由渲染层决定是否输出 |
| `toc` | 目录 | `single` | 可选 | 在 body 之前 |
| `body` | 正文 | `flow` | **必选** | 在 cover/colophon/toc 之后 |
| `closing` | 结尾 | `single` | 可选 | 必须最后一个出现 |

- 每类部件**至多出现一次**（P0）。
- `pageMode ∈ {"single", "flow"}`：单页部件（封面/扉页/目录/结尾）与流式部件（正文）。
- `optional: true` 仅表示"默认可省略"，渲染时由规则/招标条款决定是否输出（扉页、结尾）。

示例：

```json
"structure": [
  { "part": "cover", "pageMode": "single" },
  { "part": "colophon", "pageMode": "single", "optional": true },
  { "part": "toc", "pageMode": "single" },
  { "part": "body", "pageMode": "flow" },
  { "part": "closing", "pageMode": "single", "optional": true }
]
```

## 4. styleRef——样式引用（十五组，id 必须取自 layout-presets.json）

```json
"styleRef": {
  "preset": "single-column",     "palette": "deep-indigo",
  "cover": "full-block",         "decoration": "standard",
  "font": "gov-gongwen",         "imageRatio": "mid",
  "imageRule": "hybrid",         "imageLayout": "split-h",
  "pageSetup": "p1-standard-a4", "headingSystem": "h1-gbt-arabic",
  "tocStyle": "t1-jianyu-auto",  "tableStyle": "tb1-three-line",
  "captionSystem": "c2-cy-chapter", "paragraphStyle": "pa7-jianyu-15",
  "headerFooter": "hf1-classic-enterprise"
}
```

- **十五组键名固定**：`preset / palette / cover / decoration / font / imageRatio / imageRule / imageLayout /
  pageSetup / headingSystem / tocStyle / tableStyle / captionSystem / paragraphStyle / headerFooter`。
- 每个键的值必须落在 `layout-presets.json` 对应组的 `id` 集合内（校验器逐一比对）；
- **允许缺省**：未写的键自动回退 `sources.DEFAULT_LAYOUT` 的默认值（"缺省键回默认"），便于最小模板。

## 5. placeholders——占位符绑定

键名规范：小写字母开头，仅 `a-z 0-9 _`，≤32 字符（与 docxtpl 的 `{{ }}` 风格一致）。

值规范二选一：

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 文字占位 | `{{ 键名 }}`（键名同键规范） | `"enterprise_name": "{{ enterprise_name }}"` |
| 图片占位 | `【图片占位：类别】` | `"site_photo": "【图片占位：施工现场】"` |

## 6. rules——规则

P0 识别键：

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `bidMode` | `明标` / `暗标`（`rules.BID_MODES`） | 驱动暗标派生（见 §7）；非法值报错 |
| `darkFontSafe` | bool | 明标模板兼容字段，暗标时恒为真 |
| `coverUnderlay` / `pageBreak` / `tablesOnePage` | bool | 兼容/扩展位，P0 校验不强制 |
| 未知键 | — | 仅提示（warn），不阻塞 |

## 7. 暗标派生（确定性规则，无人工二选一）

`rules.bidMode == "暗标"` 时，派生逻辑（`dark_derived`，id 以 layout-presets.json 实际预设为准）：

| 组 | 铁律 | 不合规时 |
| --- | --- | --- |
| `font` | 强制 `dark-safe` | 报错（合规校验）；派生时强制替换并记 notes |
| `imageRule` | 二选一：`dark-safe-img`（暗标安全）/ `no-source`（无图源） | 报错；派生时安全降级 `no-source` 并记 notes |
| `headerFooter` | 二选一：`hf9-dark-none`（无页眉页脚）/ `hf10-dark-page-only`（仅页码） | 报错；派生时安全降级 `hf9-dark-none` 并记 notes |
| 微观六组 | `pageSetup / headingSystem / tocStyle / tableStyle / captionSystem / paragraphStyle` 按招标条款自动注入，**不开放选择** | styleRef 显式指定时仅提示（info），派生值回默认 |

暗标校验失败即拒绝落盘/出样张（err 级），确保暗标铁律不可绕过。

## 8. 命令用法（无 UI 完整可用）

```text
python scripts/bidcraft.py tpl-design --list                          # 模板清单 + 校验状态
python scripts/bidcraft.py tpl-design --show <file>                    # 概览 + 校验 + 暗标派生后 15 组样式
python scripts/bidcraft.py tpl-design --validate <file>                # 只校验，输出问题清单（--json 结构化）
python scripts/bidcraft.py tpl-design --apply <file> --confirm         # 校验→落盘登记→写后回读校验（防覆盖）
python scripts/bidcraft.py tpl-design --specimen <file>                # 按模板出样张 docx（P0 以版面范式驱动）
python scripts/bidcraft.py tpl-design --list --json                    # 全部命令支持 --json 机读输出
```

- `--apply` 未带 `--confirm` 时 dry-run（只校验不写盘）；
- 目标同名存在时拒绝覆盖；
- `--specimen` P0 以 `styleRef.preset` 驱动 tech-layout 样张机制（内置样例正文或 `--project` 真实项目），
  其余 14 组样式由模板 styleRef 承载展示——**P1 模板驱动渲染分支落地后全映射**。

## 9. P1 路线（本文件之外）

1. 渲染引擎 `template.json` 驱动分支：structure→部件渲染、placeholders→填充、暗标派生→export 注入；
2. M2 母版 docx 拆解回流（部件库）；
3. SKILL.md §7 对话工作流（无 UI 闭环操作手册）；
4. P2 工作台原型（HTML 三栏）与 P3 平台对接（`/api/template/*` 注册为平台工具）——UI 只是描述层的可视外壳。

## 1. 目标与原则

- **产物皆可改**：系统生成的一切文件，人工均可直接修改（不设文件级写保护；冻结版项目模板的"只读"语义见 M2 需求对齐 D11，冻结标记=元数据+版本号，解冻走流程）。
- **改动可识别**：系统能自动发现"哪些产物被人工改过、怎么改的"。
- **演进受控**：从人工修改中提炼系统功能完善点，**应用前必须产出评估报告、经人工确认**。
- **版本可追溯**：每个产物有基线（哈希+版本+生成器版本+时间），任何应用更新后刷新基线并记录。

## 2. 机制总览（六步）

```
① 基线登记   产物落盘时登记：相对路径 + SHA-256 + 版本 + 生成器版本 + 时间 → 产物基线清单.json
② 自动检测   每轮任务开始时哈希比对（秒级）→ 未变 / 已改 / 新增 / 缺失
③ 深度差异   对"已改"产物提取结构化 diff（docx 文本级 / json/csv 行级 / 表格逐格）
④ 评估报告   自动生成《系统功能更新评估报告》md：改动摘要 + 完善点建议 + 影响面/风险 + 回滚方案
⑤ 人工确认   用户审报告 → 全部采纳 / 部分采纳 / 驳回
⑥ 受控应用   数据层：更新基础模板/登记清单/占位符映射并刷新基线；代码层：改代码 + 回归 + 记录；均记变更日志
```

## 3. 数据落位

```
<软件根>/<企业>/
├── 产物基线.json                      ← 全企业产物基线清单（企业级+项目级统一在此登记）
└── 产物反馈/
    ├── 评估报告_YYYYMMDD_HHMMSS.md     ← 每次审计后生成的评估报告（人工审阅）
    └── 变更日志.md                     ← 已应用的更新记录（追加）
```

基线条目 schema：

```json
{
  "id": "uuid8",
  "层级": "项目级",                      // 企业级 / 项目级
  "项目": "马鞍山和县化工园…"（项目级时）,
  "产物类型": "项目模板",                 // 投标要点/素材清单/素材对照/格式契约/模板文件/项目模板/商务标/…
  "相对路径": "项目级/…/项目模板/开标一览表.docx",
  "sha256": "…",
  "版本": "v1",
  "生成器": "m5-project-template-gen",
  "登记时间": "2026-10-03T19:40:00",
  "备注": ""
}
```

## 4. 识别机制

### 4.1 自动检测（每轮任务开始）
- agent 执行 `fb-audit --quick`：遍历基线清单，比对当前文件哈希 → 输出四类：
  - `未变`：哈希一致；
  - `已改`：文件在、哈希不一致（**人工修改的主要信号**）；
  - `新增`：磁盘有、基线无（需排除系统自身文件）；
  - `缺失`：基线有、磁盘无。
- 检测到"已改/新增/缺失"→ agent 向用户提示，并按需进入深度差异。

### 4.2 手动深度差异（audit 命令）
- `fb-audit [--path <相对路径>] [--full]`：对指定/全部已改文件做结构化 diff。
- docx：提取段落+表格文本后逐行/逐格比对（复用格式契约的提取逻辑）；
- txt/md/json/csv：行级 unified diff；
- 输出：文件、改动类型（段落改/表格结构改/数值改/占位符改/增删行）、改动摘要。

### 4.3 排除清单（不算"人工改动"）
- 系统自身维护文件：产物基线.json、模板台账.json/csv、素材台账、回收站清单、批次文件、_反馈目录本身。
- **占位符登记清单.md 纳入基线**（agent 维护但人工也可改，属反馈源）。

## 5. 评估报告模板（自动生成）

```markdown
# 系统功能更新评估报告
- 报告编号：FR-YYYYMMDD-NN ｜ 生成时间 ｜ 触发：自动检测 / 手动 audit

## 1. 变更概览
| 文件 | 类型 | 状态 | 原版本 | 现哈希 | 改动规模 |
|---|---|---|---|---|---|
| …   | 项目模板 | 已改 | v1 | … | 3 段/2 表 |

## 2. 差异摘要（逐文件）
- <文件>：改了什么（段落文字 / 表格行列 / 占位符 / 数值 / 增删）

## 3. 完善点建议
- 数据层：<如：基础模板「开标一览表.docx」表头 X 与契约一致，建议更新；登记清单补 Y>
- 代码层：<如：生成规则对附表 8 的行数裁剪逻辑需适配 Z；改动需跑回归>

## 4. 影响面与风险
- 涉及模块/产物/流程；代码层是否需回归（三塔层）；回滚方案

## 5. 建议动作
- 采纳项：<编号清单> ｜ 驳回项：<编号清单> ｜ 回滚：<方式>

## 6. 确认栏（待人工确认）
- [ ] 全部采纳  [ ] 部分采纳（注明编号）  [ ] 驳回
```

## 6. 受控应用（确认后）

| 层 | 动作 | 门槛 |
|---|---|---|
| 数据层 | 更新基础模板文件 / 占位符登记清单 / 占位符映射（素材清单"用途/占位符键"） | 报告确认即可应用，应用后刷新基线、记变更日志 |
| 代码层 | 更新生成规则 / 脚本逻辑 | 报告确认 + **三塔层回归全绿** + 开发日志记录，方可合并推送 |

- 应用后：`fb-baseline --refresh` 刷新受影响产物基线（新哈希+版本 bump）；写变更日志。
- 冻结版项目模板（D11）：人工修改须先走解冻流程，审核后重新冻结。

## 7. 命令集（设计，开发待后续轮）

| 命令 | 作用 |
|---|---|
| `fb-baseline --path <相对路径> [--type 产物类型] [--generator 生成器]` | 登记/刷新单个产物基线 |

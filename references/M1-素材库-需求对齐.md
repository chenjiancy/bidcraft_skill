## 一、目标与形态

**目标**：为 bidcraft skill 建立一套结构化、命名规范的投标素材库基座，支撑后续商务标、技术标、标书检查、模拟评标等模块按条件检索调用素材。

**交付形态**：纯文件系统 + 对话式交互（agent 驱动）。
- 不做独立软件界面；素材以「文件夹 + 文件」形式落盘，agent 按命名规范操作。
- 「上传 / 提示 / 归档」均由对话式交互完成；跨 WorkBuddy、豆包等 agent 平台通用。
- 机械操作（建目录、改名、移动、写台账）由确定性脚本执行；「看懂内容、判断归类」由 agent 完成。
- 后续如需上传体验升级，可叠加轻量本地界面（升级为混合模式），当前不纳入范围。

## 二、目录结构

三级层级：**企业 → 大类 → 子项**，支持随业务自由扩展（遇到新子项自动建目录）。

```
素材库/
└── <企业名>/                       ← 调用 skill 时先创建/选择企业
    ├── 资质/
    ├── 人员/
    │   └── <姓名>/                 ← 按人员姓名建文件夹
    │       ├── 注册证书/
    │       ├── 岗位证书/
    │       ├── 职称证书/
    │       ├── 身份证/
    │       ├── 毕业证/
    │       ├── 个人荣誉/
    │       ├── 退休证/
    │       ├── 返聘协议/
    │       └── 简历/
    ├── 业绩/
    │   └── <项目全名关键字_签订日期_总监>/    ← 按项目建文件夹
    │       ├── 监理合同_P0/P1...
    │       ├── 竣工报告_P0/P1...
    │       └── 备案证书_P0/P1...
    ├── 荣誉/
    ├── 财务/
    ├── 收件箱/                     ← 上传缓冲区（非正式分类）
    ├── 回收站/                     ← 删除/被覆盖的文件；30 天自动清理
    └── 素材台账.csv / .json        ← 每企业一套台账
```

- 创建企业后，初始化 **资质 / 人员 / 业绩 / 荣誉 / 财务 / 收件箱 / 回收站** 目录 + 台账文件。
- 各层级目录均可动态创建。

## 三、命名规范

> **有效期一律填「到期日」**（8 位 `YYYYMMDD`），不用起止区间；无到期日填「长期」。

### 1. 资质
| 素材 | 命名规范 | 示例 |
|------|----------|------|
| 营业执照 | `营业执照[_正副本]_到期日` | `营业执照_20281231.jpg`、`营业执照_正本_20281231` |
| 资质证书 | `资质证书关键字_到期日` | `房屋建筑工程甲级_20281222` |
| 体系认证证书 | `证书关键字_到期日` | `ISO9001质量管理体系_20280630` |
| 信用证书 | `证书关键字_到期日` | `AAA信用等级_20281231` |

### 2. 人员（按姓名建文件夹，下设子类）
| 子类 | 命名规范 |
|------|----------|
| 注册证书 | `注册证书名关键字_注册有效期_使用有效期到期日` |
| 岗位证书 | `岗位证书关键字_到期日` |
| 职称证书 | `职称等级关键字_专业` |
| 身份证 | `身份证_国徽面_到期日` / `身份证_人像面_到期日` |
| 毕业证 | `毕业证_专业` |
| 个人荣誉 | `荣誉证书名关键字_颁发日期` |
| 简历 | `简历_上传日期` |
| 退休证 | `退休证[_关键字]_长期` |
| 返聘协议 | `返聘协议[_关键字]_到期日` |

- **多页文件**：末尾追加 `_P0/_P1` 序号，**按上传顺序**排列（P0 为首页）。

### 3. 业绩（按项目建文件夹）
- 文件夹名：`项目全名关键字_签订日期_总监`（总监取**合同中的总监姓名**，无则标「无总监」）
- 文件命名：`监理合同_P0/P1`、竣工报告、备案证书等同此规范。

### 4. 荣誉
- 文件命名：`证书名关键字_颁发日期`
- 涵盖：优秀监理企业、先进监理企业、监理示范工程、标准化工地及各奖项。

### 5. 财务
- 文件命名：`证书名关键字_到期日`（如 基本户开户许可证）。

### 6. 收件箱
- 上传缓冲区，不作正式分类；上传方式不限。

## 四、通用规则

1. **有效期 = 到期日** → 统一 8 位 `YYYYMMDD`；无到期日记「长期」，即 `证书名关键字_长期`。
2. **字段无法识别** → 弹窗提示用户自行决定命名方式，并允许继续操作。
3. **动态建目录** → 支持各层级随业务扩展；新增大类沿用通用式 `关键字_日期`，该类专属字段由用户临时定义。
4. **多企业隔离** → 支持按企业创建素材库，各企业独立；企业目录用企业全名（重名时加统一社会信用代码后 6 位）。
5. **企业归属校验** → 素材多与企业强关联；识别依据优先级 **文件名 → 文档正文 → 图像 OCR**；若在 A 企业上传了疑似 B 企业资料，**弹窗提醒待用户确认**。
6. **多页归组** → 归档确认时由用户**手动圈选**同组。
7. **归档方式** → **半自动确认制**：系统给出建议命名 + 目标路径，用户确认/修改后执行。
8. **素材台账** → **JSON/CSV**，归档时同步登记，供后续模块检索。
9. **归档保持原格式** → 归档后文件扩展名 / 格式与上传时保持一致，不做转换。
10. **删除 / 覆盖 → 回收站** → 被删除或被覆盖替换的文件，移入企业下 `回收站/`，**30 天自动清理**；同名 / 重复素材由**弹窗提示用户确定**。
11. **关键字清洗** → 关键字中不得含 `_`；Windows 非法字符 `/ \ : * ? " < > |` 与 `_` 一律替换为 `-`（保结构不被撑破）。
12. **无日期兜底** → 无到期日记「长期」；日期不可考（如荣誉无颁发日期）记「日期不详」。

## 五、业务流程

```
① 进入企业 → ② 合规巡检 → ③ 用户确认 → ④ 收件箱逐张上传 → ⑤ 归档
```

| 阶段 | 主体 | 内容 |
|------|------|------|
| ① 进入企业 | 系统 | 选/建企业 → 初始化目录与台账 → 会话锁定该企业 |
| ② 合规巡检 | 系统 | 扫描分类目录中**未经收件箱**的素材（= 非常规上传）+ 命名规范性 → 出问题清单 |
| ③ 用户确认 | 用户 | 逐条决定：删除重传 / 保留归档 |
| ④ 收件箱上传 | 用户 | 打开收件箱，逐张上传（不批量）→ 登记顺序 → 暂存 |
| ⑤ 归档 | 系统+用户 | 按序分配 P0/P1 → 生成建议命名+路径 → 用户确认 → 改名移动 + 写台账 + 清空收件箱 |

**上传环节内部逻辑**（一次「打开收件箱」= 一个上传批次）：

| 逻辑点 | 处理方式 |
|--------|----------|
| 顺序 | 每张记 `(文件名, 写入时间, 序号)`；时间撞车则提示用户确认 |
| 暂存 | 文件先躺收件箱，归档指令前不归类 |
| 命名 | 上传保留原名，归档时才按规范改名 |
| 多页归组 | 归档时用户手动圈选同组 |

## 七、技术方案概要

- **操作层**：agent 按规则直接建目录、改名、移动文件（固化为 Python 脚本，放 skill 的 `scripts/`）。
- **顺序登记**：收件箱内维护批次清单 `收件箱/_batch.json`，记录 `(文件, 写入时间, 序号)`。
- **台账**：`素材台账.csv` + `素材台账.json`（每企业一套），登记 分类 / 路径 / 关键字 / 日期 / 归属企业 / 上传日期 / 原始文件名。
- **合规巡检**：以台账作为「已归档」权威记录 —— 分类目录中无台账记录的文件即「非常规上传」；命名不符规范者一并列出。
- **回收站**：每次调用 skill 时检查 `回收站/` 内文件年龄，超 30 天自动清理。
- **内容识别**：企业归属校验与关键字段提取，文件名解析由脚本完成；正文字段 / 图像 OCR 由 agent 多模态能力完成，结果回传脚本比对。
- **交互**：所有「弹窗 / 提示 / 确认」以对话式交互实现。

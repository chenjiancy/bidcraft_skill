## 三、一期原型范围（只做这些）

1. **三区工作台**：左区=15 组预设库导航；中区=画布预览（A4 页面示意：封面/页眉页脚/标题层级/正文段落/表格/图片位/配色/边距，明暗标联动）；右区=属性面板（当前组 10 套选择 + 套参数展示/编辑：palette 色值、font 字号、pageSetup 边距、paragraphStyle 行距、headerFooter 页眉页脚等关键参数）
2. **明/暗标双模式**：暗标开关联动锁定/注入/禁用规则（S4/S5/S6）
3. **快捷应用**：默认组合 + 5 套 recommendedCombos 一键套用
4. **组合校验**：输出 check 列表（error/warn/info），含暗标合规与参数合理性
5. **导出**：组合 JSON（layout + overrides + checks）下载 + 复制
6. **出样张指引**：对接 `tech-layout --preview <preset>` 的说明

**明确不做**：不引入拖拽画布（Q4=A）；不改 layout-presets.json 源文件（S7）；不接 tech-export/Word COM（D-1/D-2）；不做商务标母版工作台（二期 B）。

## 四、验证方式

- HTML 自检：`html` skill `scripts/shot.py`（桌面+移动截图，0 error 0 warning）
- 数据保真：原型内联数据由脚本从 layout-presets.json v1.4 提取，逐组数量=10、默认位与暗标标记与文件核对
- 校验逻辑：手工用例（暗标下选 image-underlay → error；明标任意组合 → 通过）在原型内自测

**规则/需求**：用户提出本项目为 skill+agent 架构，agent 由安装平台（豆包/WorkBuddy 等）提供；当前前端 UI 未与 agent 平台对接、不具备 agent 能力、UI 实际不可用。用户拍板：「所有实现都要落实到 skill\文档\代码层面，就是不需要 ui 就可以实现完整功能」，要求落实 A（对话优先）+ B（本地 HTTP 桥）。

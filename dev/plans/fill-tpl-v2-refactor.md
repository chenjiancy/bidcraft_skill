# fill-tpl 重构方案（v2.0 布局样板范式）

日期：2026-10-19　状态：待审　关联规范：模板库\_模板制作规范.md v2.0

## 一、目标

将 M5 fill-tpl 的资格证明/业绩填充从「坐标 + 人名硬编码」（CELL_MAP / p("陈云",…)）重构为
「**按类别关键词定位占位段 → 样板行/页按素材清单数量复制 → 类别聚合素材依序消费 → 缺图披露**」，
实现**模板=版面样板、素材清单=数据**，换人/换机构不改模板。

## 二、现状问题（重构对象）

| 问题 | 现状 | 后果 |
|---|---|---|
| 坐标硬编码 | `build_maps` 生成 CELL_MAP `((52,0,0), p("陈云","职称",0), …)` | 绑定大成资格表结构，恒信结构不同即错位 |
| 人名硬编码 | `p("陈云","职称",0)`、占位文案「中级职称证书｜黄大海」 | 换人即失效，模板与数据耦合 |
| 数量固定 | 人员配备表 5 行、简历 5 份、业绩明细表 3 页铺满模板 | 素材清单 3 人/5 条业绩时无法增删 |
| 未列不生成缺失 | 素材清单未列类别仍按模板硬填 | 产生清单外内容 |

## 三、重构设计

### 3.1 占位索引层（模板识别，新增）

扫描模板全文（正文段 + 文本框段 + 表格内段），输出该件母版的**占位索引**：

- **文字键清单**：`{{ }}` 分类为
  - 通用键（V 表键：project_name/company_*/bid_date/姓名/agent_* 等）→ 直填；
  - 行级键（`{{ 人员姓名 }}`/`{{ 人员年龄 }}`/… → 人员配备样板行；`{{ 业绩业主单位 }}`/… → 业绩样板行/页）。
- **图片类别序列**：`【图片占位：类别】` 按出现顺序记录（类别 + 段落定位 + 所在表格/文本框）。
- **样板定位**：含行级键的行 = 样板行；含 `{{ 人员姓名 }}` 的简历表及其后证书图框段组 = 简历样板组。

### 3.2 样板复制层（新增，核心引擎）

按素材清单数量深拷贝 XML 节点（保留格式/合并单元格/文本框），遵循：

| 结构 | 样板 | 复制源 | 复制数 |
|---|---|---|---|
| 人员配备表 | 1 行样板 | `{{ 人员姓名 }}` 行 | len(personnel) |
| 简历表+证书图框组 | 1 份样板组 | 见 3.2.1 样板组界定 | len(personnel) |
| 业绩汇总表 | 1 行样板 | `{{ 业绩业主单位 }}` 行 | len(performance) |
| 业绩明细页 | 1 页样板 | 明细表及图框段 | len(performance) |

规则：清单数 > 样板数 → 复制补齐；清单数 < 样板数 → 删除多余样板；复制后行级键按对应素材对象填值。

#### 3.2.1 简历样板组界定（人员锚点法）

- **组起点** = 人员锚点段：含 `{{ 人员姓名 }}` 的标题段，或含 `{{ 人员姓名 }}` 的简历表。
- **组终点** = 下一个人员锚点段之前（两者之间无分页符时也按锚点分段）；若下一内容为分页符且其后无锚点段，则到分页符为止。
- 组内证书图框段 = 该人专属：**组内图片按该人员对象的证书数组填充，组间不串**（不参与全局依序消费）。
- **v2.0 人工制作约定（强制）**：证照区每个人员的证书图框组前面放一个「{{ 人员姓名 }}」标题段作为锚点；简历样板页（简历表 + 同页证书图框）按上述规则天然成组。

**示例（母版样板页，仅一份）：**
```
[第X页]
{{ 人员姓名 }}            ← 人员锚点段（标题）
简历表：| {{ 人员姓名 }} | {{ 人员出生年月 }} | {{ 人员学历 }} | {{ 人员专业 }} | {{ 人员职称 }} | {{ 人员职务 }} |
【图片占位：职称证书】（文本框）
【图片占位：岗位证书】（文本框）
【图片占位：身份证】（文本框，正反同页）
──────────── 分页符 ────────────
```
素材清单 personnel=[陈云,黄大海,陈阳,裴友谊,阮旭]，fill 复制为 5 组：
- 第 1 组（陈云）：锚点/简历表填陈云数据；职称证书框←陈云职称证书、岗位证书框←陈云岗位证书、身份证框←陈云身份证；
- 第 2 组（黄大海）：填黄大海数据 + 黄大海证书；…（组内取数、组间不串）。

### 3.3 类别聚合填充层（改造）

类别 → 素材路径聚合（按素材清单 schema）：

| 占位类别 | 聚合来源 |
|---|---|
| 总监注册监理工程师证书 | 总监的「注册证书」（总监识别见下） |
| 高级工程师职称证书 | 总监「职称证书」中高级职称部分 |
| 职称证书 / 岗位证书 | **非总监人员**职称证书展平 / 岗位证书展平（按 personnel 顺序） |
| 身份证 / 社保证明 | 全部人员身份证展平 / social_security_required.paths |
| 企业资质证书 / 企业法人营业执照 / 开户许可证 | qualification_required 按名称匹配 |
| 三体系认证证书 | iso_certificates |
| 先进监理企业证书 / 监理示范工程 / 优秀总监证书 | honors 按名称关键词匹配 |
| 业绩材料 | performance.paths 展平 |

**总监识别与职务口径**：
- **总监识别**：职务字段含「总监」/「总监理工程师」者为总监；**personnel[0] 仅为兜底**（职务字段缺失/异常时用首位）。
- **专业监理工程师 / 监理员不参与图片类别识别**：职务是数据，直接填入 `{{ 人员职务 }}`（配备表/简历/开标一览表），模板不按职务细分图片类别。
- 人员区证书聚合 = 非总监人员对应字段展平、按 personnel 顺序依序消费；**某人员无某类证书（如监理员无岗位证书）→ 该类自动少一张**，模板占位按实际数量消费，多余图框删框+缺图披露。

填充：按模板中该类别占位出现顺序依序消费聚合列表；图片按文本框/图框尺寸等比缩放（image_spec v2.0）插入，删占位文案。
简历样板组内的图片按 3.2.1 规则**按人员对象取数**，不参与全局依序消费。

### 3.4 未列不生成（新增披露）

- 类别素材数 = 0 → 该图框不填充、删除占位段，计入缺图清单（类别 + 缺 N 张）。
- 样板复制后无对应素材 → 同缺图披露，不静默硬生成。
- 固定内容（企业简介、组织机构框图、固定条款）不受驱动影响（_商务标固定素材.json 豁免）。

### 3.5 兼容与迁移

- **旧母版**（大成招标式 9 件 / 采购式 6 件、恒信招标式 8 件）：按 v2.0 人工重做（用户已选人工制作路线）。
  迁移期 CELL_MAP/YJ_MAP 保留为兼容分支，v2.0 母版走新引擎；新引擎验证通过后删除兼容分支。
- fill-tpl 骨架文件列表（TPL_FILES / TPL_FILES_PH）与项目模板深拷贝链路不变。

## 四、素材清单口径核对（重构前提）

重构前需确认素材清单 schema（`_模板制作规范.md` v2.0 第三节已列键名），重点核对：
1. personnel 字段名：`职称证书`/`岗位证书`/`注册证书`/`身份证`/`一级造价师证书`/`经历`（数组结构）；
2. performance 字段名与 paths 展平口径；
3. honors / iso_certificates / qualification_required / social_security_required 名称匹配关键词。

## 五、实施步骤（待审后执行）

1. **占位索引扫描**：docx_tools 增 scan_placeholder_index（正文+文本框+表格内段；类别序列+样板定位）→ 单测。
2. **样板复制引擎**：xml 深拷贝（行/表/段组，保留格式与合并单元格）→ 单测。
3. **类别聚合填充**：聚合映射表 + 依序消费 + 缺图披露 → 以恒信基准数据构造素材清单样例端到端试跑。
4. **回归与收尾**：三塔回归全绿 → dev/notes 日志回填 → commit + PR。

## 六、验收标准

- 素材清单 5 人 → 配备表 5 行、简历 5 份；3 人 → 3 行 3 份（模板不改）。
- 图片按类别+顺序正确消费，A 人证书不进 B 人框；缺图披露准确（类别+张数）。
- 清单未列类别 → 商务标不出现；固定素材豁免正常。
- unit/int/e2e 三塔全绿。

## 七、风险与待确认

1. **总监识别口径**：职务字段含「总监」/「总监理工程师」者为总监，personnel[0] 仅兜底；专业监理工程师/监理员为数据（{{ 人员职务 }} 直填），不参与图片类别识别——需与素材清单 schema 固化（写入规范，防后续人员排序/职务变更）。
2. **简历样板组界定**：模板中「简历表 + 其后证书图框段」如何界定为一组——约定：简历表后到下一分页符前的图框段归该人（v2.0 人工制作时按此排版）。
3. **样板复制与合并单元格兼容**：人员配备表/业绩表如有合并单元格，复制时需按 XML 物理结构深拷贝（docx_tools 已有 dim5 结构读取支撑）。
4. **旧母版迁移周期**：人工重做 3 个机构 3 骨架期间，兼容分支保留，新引擎并行验证。

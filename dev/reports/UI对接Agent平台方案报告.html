前端 UI 对接 Agent 平台 · 方案调研报告

针对 bidcraft（skill+agent 项目，agent 由豆包/WorkBuddy 等平台提供）：当前版面设计器 UI 为纯前端原型，未接入 agent 能力、实际不可用。本报告给出经联网查证（2026-10-23）的 6 条接入方案与推荐路径。

一、问题诊断

现状：能力在 SKILL.md + scripts/bidcraft.py（CLI：tech-layout/apply-combo/outline/export 等）；前端 版面设计器-工作台V1.html 是单文件原型——内联 RAW 数据、无后端、无 agent 通道，故"UI 不可用"。
平台规则（查证）：
  • 豆包：Skill = 任务扩展单元，结构与本项目同构（SKILL.md/scripts/references/assets）；外部服务须经「连接器」或「已注册工具」接入，Skill 不应直接暴露外部 API；开放平台提供 OpenAPI 与开发者平台（MiniApp 支持 MCP endpoint）；火山方舟 Managed Agent 可接入豆包企业版「工作伙伴」。
  • WorkBuddy：技能市场 + 自定义技能（可对话创建）；自定义技能可把任意 HTTP API 包装成可调用工具（本地 127.0.0.1 服务已有社区实践）。
  • MCP 生态：mcp-skill-bridge（本地 skills 目录 → MCP server）、a2a-mcp-skillmap（A2A agent → MCP 工具）等桥接工具成熟。

二、六条方案对比

方案接入通道UI 形态部署迁移量平台门槛
A 对话优先
零成本立即可用		 纯 Skill：设计器能力全部转成自然语言指令 + 既有 CLI 闭环（tech-layout/apply-combo/outline/export） HTML 降级为「产物视图」（样张/报告/校验单查看器） 无需新增服务 低（写提示词编排，复用全部脚本） 无（豆包/WorkBuddy 安装 Skill 即用）
B 本地 HTTP 桥
恢复可操作 UI		 bidcraft CLI 包本地 HTTP/SSE 服务（/api/layout /api/combos /api/export），前端 fetch 调用；平台侧把同服务注册为工具 现有设计器改造为「可操作台」（本地服务执行真实 CLI） 本地常驻服务（FastAPI/Flask） 中（新增 server 层 + 前端请求改造） 低（本地回环；注册工具走平台鉴权/审核）

企业分发		 火山方舟构建 Agent（挂 bidcraft 工具/OpenAPI）→ 接入豆包企业版「工作伙伴」，复用对话/任务展示/产物交付 对话为主；UI 留作外部 Web 视图 方舟云端 中（Agent 编排 + 工具注册） 中（方舟账号 + 企业版）
E 豆包 OpenAPI

F WorkBuddy HTTP 技能
单平台		 bidcraft 包 HTTP 服务，WorkBuddy 自定义技能注册接口（POST /api/…），对话中调用 对话 + 本地 UI 双通道 本地常驻服务 中 低（WorkBuddy 明确支持自定义技能包 HTTP API）

三、推荐路径（分三步，每步可独立验收）

第 0 步（本周）　A 对话优先：Skill 编排提示词 + CLI 闭环 → UI 标注「演示原型，实际工作流在对话中执行」→ 立即可用 　↓ 第 1 步（短期）　B/F 本地 HTTP 桥：bidcraft-server 暴露 /api/* → 设计器改造为可操作台 → WorkBuddy 自定义技能注册同一服务 　↓ 第 2 步（中期）　C/D 平台化：能力包成 MCP server（MiniApp endpoint / 已注册工具）或方舟 Managed Agent 接入豆包企业版 → 设计器迁 MiniApp / 外部 Web 视图

决策建议

  • 先做 A：零迁移、不依赖平台私有 API，且 Skill 结构（SKILL.md+scripts）与豆包/WorkBuddy 官方 Skill 形态完全同构，天然可分发；"UI 不可用"的观感由产物视图（样张 docx/html、报告）承接。
  • 恢复 UI 操作性选 B：本地 HTTP 桥是双平台通用的中间形态——豆包「已注册工具」与 WorkBuddy「自定义技能」都能包装 HTTP API，一套服务两处复用。
  • 豆包深度集成选 C/D：MiniApp 的 MCP endpoint 是豆包官方给出的前端↔工具通道；方舟 Managed Agent 适合企业统一分发。两者都需准入，宜在 A/B 跑通后申报。

四、关键落地动作（对接 A+B）

  • Skill 编排：在 SKILL.md 增加"版面设计"工作流入口（触发词：设置版面/出样张/存组合/生成技术标），流程=tech-layout 查看 → 组合调整 → apply-combo 生成专家包 → outline 落盘 → export 导出 docx，全部人工确认闸门。
  • 本地服务：新增 scripts/bidcraft_server.py（仅读接口：组合清单/校验/样张渲染；写操作一律走 CLI+确认闸门，服务只做只读代理），前端 fetch 同源/回环地址。
  • 平台注册：豆包侧按「连接器/已注册工具」规范申报（鉴权、权限、安全验证）；WorkBuddy 侧用「添加技能→创建技能」注册 HTTP API（参考本地 127.0.0.1 实践）。
